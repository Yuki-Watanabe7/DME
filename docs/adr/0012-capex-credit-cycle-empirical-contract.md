## コンテキスト

部門別CAPEX・信用循環モデルの状態変数には、期待需要（`ai_exp`）・目標設備能力（`target_cap_s1`）・資本コスト（`cost_capital_s`）・計画CAPEX（`capex_plan_s1`）のように直接観測できない量が含まれる。また半導体・データセンター関連の公表統計と企業開示は、モデル部門（`S1`–`S5`）と範囲・単位・頻度・時点基準が一致しない。

[ADR 0011](0011-capex-credit-cycle-dynamics-contract.md) は方程式・パラメータ辞書（構造 35 系統・行動 44 系統・政策 3 系統）・逆較正・定常条件を確定したが、**どの量を何で観測し、どのパラメータをどう決め、何をもって検証したと言えるか**を #170 へ引き渡した。

実装後に利用可能なデータへ無理に合わせると、次が起きる。

- 指数（FRB 産業生産指数・BLS PPI・FRB 設備能力）を水準として扱う。
- 企業開示の集計と産業統計を混在させ、集計対象企業の選定基準が記録されないまま較正する。
- NIPA・BEA の年率表示（SAAR）を四半期合計として使い、フロー変数を 4 倍に見積もる。
- `debt_s`・`int_burden_s` のように産業別内訳が存在しない系列を按分し、按分キーの任意性を隠す。
- 44 系統の行動パラメータを少数の観測系列から同時推定し、弱識別を「推定できた」と申告する。
- fit の良い履歴再生期間を事後に選び、公式景気後退判定との一致率を較正目標にする。

本決定は、これらを構造的に禁じる契約を固定する。

## 決定

1. **観測方程式を系列名マッピングとして扱わず、9 項目（`model_var`・`series`・`level_form`・`unit_conversion`・`sector_scope`・`published_basis`・`aggregation`・`methodology`・`vintage`）を備えた変換契約として定義する。**
   9 項目を欠く対応を「観測方程式を定義した」と申告しない（[観測方程式・識別戦略・検証方針](../models/capex_credit_cycle_empirical_strategy.md) §4.1）。

2. **系列 ID は候補として扱い、存在・定義・単位・基準年・季節調整・部門範囲を provider metadata または一次資料で確認してから採用する。確認前の系列で較正結果を報告しない。**
   指数系列を水準として使う場合はアンカー方式（どの期のどの水準値へ合わせるか）を必ず記載する。`y_s` は FRB 産業生産指数の変化率のみを用い、水準は BEA 産業別実質産出額へ帰属させる（同 §4.1・§4.3）。[ADR 0004](0004-keen-empirical-calibration-strategy.md) の「指数か比率かを検証せず直接利用しない」義務を継承する。

3. **`aggregation` / `allocation` / `proxy` を区別して記録し、`allocation` は按分キーの感応度なしに、`proxy` はずれの方向（過大/過小/不定）の記載なしに用いない。**
   ずれの方向が「不定」の proxy について検証で符号を主張しない。3 種が連鎖する場合は各段の出力を保持し最終値のみを保存しない（同 §4.6）。

4. **モデルが要求する時点基準（`SUM` / `EOP` / `AVG`）と観測の集計方式（`:sum` / `:end` / `:mean`）を必ず対応させ、NIPA・BEA の年率表示は `÷ 4` で四半期合計へ換算する。**
   換算の有無を `unit_conversion` へ明記する。この換算漏れはフロー変数を 4 倍に見積もる系統的誤りであり、資金調達恒等式との照合まで検出されない（同 §4.2）。

5. **主要変数を `D`（直接観測）/ `C`（複数系列から構成）/ `P`（proxy）/ `E`（潜在・逆較正）/ `A`（観測不能・シナリオ仮定）へ排他的に分類し、`P` の水準 fit を検証の根拠として提示せず、`E` / `A` について fit を計算しない。**
   分類は変数の性質ではなくデータソース境界に条件付きであることを明示する（同 §3.1・§10.2）。

6. **企業開示に依拠する系列を初期MVPの推定・較正の入力に用いない。比較・定性参照の用途に限る。**
   集計対象企業の選定基準が再現性を左右するためである（[部門境界と変数定義](../models/capex_credit_cycle_sectors_variables.md) §9-5）。帰結として `S1` の収益ブロック（`sales_s1`・`profit_s1`・`ocf_s1`・`cash_s1`）が観測に接続されず、増幅ループ `R1a` を実証的に検証できない。比較目的で提示する場合は選定企業の一覧と集計規則を出力へ添える（同 §6.4）。

7. **`ai_exp` を `A` 分類とし、起点ショック（`SH-EXP`）の規模を観測から較正しない。規模は走査結果として提示する。**
   したがって `peak(dY)` の絶対的な大きさに実証的な意味を与えられない。判定問題の回答は「どの条件で何が起きるか」に限られ、「どの程度悪化するか」の実証的推定ではない（同 §3.3-2・§7.5・§11-9）。[ADR 0010](0010-macro-event-scenario-contract.md) の magnitude 捏造禁止と感応度併記義務に対応する。

8. **初期MVPは `:latest`（最新 vintage・確定値）のみを用い、`:as_of` モードを実装しない。`DataSeries` 型を変更しない。**
   vintage を扱えないまま `:as_of` を実装したと申告しない（[シナリオ時間軸](../architecture/scenario_time_semantics.md) §6.3 の契約）。帰結として「その時点で判断できた」という主張を一切行えない（同 §2.4・§11-4）。

9. **標本期間の固定値を決めず、必須系列の共通利用可能期間から決定論的に算出する。欠損を `0` へ変換せず、既定で暗黙補完しない。**
   四半期ラベルを数値時間へ変換した共通軸で inner join し、端点を決めた系列（`binding_series`）を記録する（同 §2.2・§2.3）。

10. **逆較正が必要とする定常水準を、baseline 期間（助走 8 四半期）の観測平均として算出する。トレンド除去・フィルタを行わない。**
    定常水準セット（`steady_state_targets`）を逆算後のパラメータと併せて保存する。逆算後のパラメータのみを保存しない。自由度なしの整合条件（`capex_exec_s1^{ss} = st_delta_s1 · cap_s1^{ss}`）が観測と乖離する場合、乖離をゼロにするために入力を調整せず `ss_residual` として報告する（同 §5）。[ADR 0007](0007-sfc-integration-contract.md) の「不整合を自動補正せず構造化する」方針を継承する。

11. **全パラメータを `FIX` / `CAL-SS` / `CAL-OBS` / `EST` / `SCN` / `SENS` の 6 区分へ排他的に割り当て、`bh_` の一部のみを `EST` とする。**
    `st_` は会計・技術定義または逆較正から、`pl_` は制度から与える。シナリオ入力（ショック規模・形状・時点・初期状態）と診断閾値は `parameters` に含めない（[動学方程式](../models/capex_credit_cycle_equations.md) §13.1 を継承。同 §7）。

12. **推定を 7 ブロック（`EB-1`–`EB-7`）へ分割し、ブロックを跨いだ同時推定を既定にしない。推定順序を `EB-1` → `EB-3` → `EB-4` → `EB-6` → `EB-7` → `EB-5` → `EB-2` に固定する。**
    観測が最も揃うブロック（金融条件・生産在庫）を先に確定し、識別が弱いブロック（CAPEX・資本コスト）を後に置く。ブロックが必要とする観測系列が 1 つでも欠ける場合、当該パラメータを `CAL-OBS` または `SENS` へ落とし推定しない。順序を記録する（同 §7.4）。

13. **objective を方程式別残差とし、軌跡全体を積分して合わせる方式（trajectory matching）を初版に採らない。**
    非線形・閾値により目的関数が不連続になるためである。重みは方程式ごとの観測標準偏差の逆数を既定とし、単一の総合スコアへ集約しない（同 §7.4-3・§7.4-4）。[ADR 0004](0004-keen-empirical-calibration-strategy.md) の ODE residual 採用と同型の判断である。

14. **弱識別時の対応（`W1` 固定へ降格 / `W2` 範囲報告 / `W3` 複数仕様併記 / `W4` 感応度のみ）を推定前に規則として割り当て、推定後に選ばない。**
    適用した事実・適用先・元の区分を記録する。標準誤差を報告しない（objective の曲率は分散推定ではない）。**弱識別を理由に推定対象を増やさない**（同 §8.3）。

15. **`bh_alpha_capex_s1`（CAPEX 調整速度）と `bh_cc_elas_s1`（資本コスト弾性）を同時推定しない。`cost_capital_s` が潜在であるため `bh_cc_lend` / `bh_cc_equity` / `bh_cc_fc` を `W1`（固定）とする。**
    `ai_exp` が観測不能であるため、`bh_alpha_capex_s1` は `ai_exp` の 3 代替仕様それぞれで推定し 3 値を並べて報告する（`W3`）。単一値を採らない（同 §8.2 `ID-1`・`ID-2`）。

16. **`ext_demand_s` を残差として構成することを認めるが、残差であることを出力に明記し、負値をクリップせず、`order_s` を超える分散を識別失敗として報告する。**
    この残差は測定誤差・部門範囲の過大・配分比の誤りをすべて吸収するため、水準・変動を「モデル外需要の推定値」として提示しない（同 §4.3）。

17. **Q4（金融緩和による遮断の判定）を履歴再生から行わない。理論シナリオ（`Sc3` vs `Sc4`）の反実仮想比較に限定する。**
    モデルは政策反応関数を持たず `policy_rate` を外生とするため、履歴再生で実現値パスを外生入力として与えると緩和効果と自然回復が分離されず、緩和効果が過大に帰属される（同 §8.2 `ID-6`）。

18. **`A`（増幅度）を観測から計算しない。**
    `A` は同一実装内の `credit-off` 反実仮想でのみ定義される（[分析契約](../models/capex_credit_cycle_analysis_contract.md) §3 Q2・[責務境界](../models/capex_credit_cycle_model_boundaries.md) §2.4）。履歴再生では信用条件が悪化した局面と安定な局面で**モデルの `A` が異なるか**を報告し、観測の増幅を推定したとは述べない（同 §10.3）。

19. **診断閾値（契約 §4.2 の深さ・持続性・`breadth`）を較正しない。感応度のみを報告する。**
    履歴再生で公式景気後退期と一致するよう閾値を選ぶことは、[分析契約](../models/capex_credit_cycle_analysis_contract.md) §4.1 が禁じる「一致率の目的関数化」に当たる。`breadth` は実体部門 4 のため 0.25 刻みの離散値しか取らず**連続的な較正が原理的に不可能**であり、感応度は「2 部門以上 / 3 部門以上 / 4 部門」の 3 通りの離散比較として報告する。`E1`（家計所得が `S1` 需要へ還流しない）によるバイアス評価として `S1` を除いた 3 部門版 `breadth` を併記する（同 §7.6）。

20. **履歴再生候補の必要条件（`NC-1`–`NC-7`）を先に固定し、期間の最終選定を実装フェーズへ委ねる。`NC-7` を満たす最小の組を選び、fit の良い期間を事後に選択しない。**
    選定した候補と除外した候補の除外理由を記録する。AI・データセンター CAPEX 局面（2023 以降）は評価 20 四半期を確保できず baseline が定常近傍でないため履歴再生に用いない（同 §9）。

21. **履歴再生の baseline も成長率ゼロの定常状態とし、観測側のトレンドを除去しない。**
    観測の `dx_t` はトレンド分を含み、モデルの `dx_t` は含まないという非対称性を、検証 metric の解釈に必ず添える（同 §9.3）。[ADR 0011](0011-capex-credit-cycle-dynamics-contract.md) の baseline 定義を実データ接続へ拡張したものである。

22. **数値fit・動学構造・比較・数値解法頑健性を 4 レイヤーへ分離して報告し、単一の総合スコアへ集約せず、実証層で単一の pass/fail 閾値を課さない。**
    calibrated が literature/default より悪化した場合は明示し隠さない。弱識別・境界張り付き・打ち切り・会計違反・`runup_deviation`・`ss_inconsistent` を `warnings` へ集約する（同 §10）。

23. **`SimulationResult` 型を変更せず、実証層の情報は methodology metadata と別の結果型で保持する。モデル層は `DataSeries` を受け取らず、データ品質フラグを渡さない。**
    モデル層が外部 API を呼ばない構造を維持する。取得失敗は較正層で例外として扱い、欠損を既定値で埋めて `simulate` を実行しない（同 §6.5）。[ADR 0009](0009-capex-credit-cycle-model-responsibilities.md) 決定 8 を継承する。

24. **実証fitを因果妥当性・景気後退確率・投資助言・「その時点での判断可能性」へ読み替えない。**
    出力は観測（`D`/`C`/`P`）・逆較正（`CAL-SS`）・推定（`EST`）・モデル出力・診断・感応度を分離した根拠階層として提示する（[ADR 0005](0005-keen-ai-explanation-contract.md) の category へ写像。同 §10.6・§11）。

## 1. なぜ観測方程式を 9 項目の変換契約とするか

| 論点 | 決定 | 根拠 |
|---|---|---|
| 系列名の対応表で足りるか | 足りない | 本モデルは 5 部門・約 60–70 の必須系列を持ち、同一の統計（Census M3・BEA GDP by Industry）から複数変数を構成する。単位・時点・部門範囲のいずれかがずれた対応は、会計恒等式との照合まで検出されない |
| 最も危険な誤り | 年率表示の未換算と指数の水準扱い | 前者はフロー変数を 4 倍にし、後者は `util_s`・`price_s`・`y_s` の水準を無意味にする。どちらも「系列を取得できた」段階では気付かない |
| 検証の所在 | `unit_conversion` と `level_form` を metadata として保存し、会計検証 12 項目（#166 §8.1）で交差確認する | 変換の記録がなければ、会計違反が変換ミスか方程式ミスか区別できない |
| `sector_scope` を必須にする理由 | NAICS 3344 は設計・製造統合、NAICS 334 は通信機器を含む。部門範囲の過大が `ext_demand_s` の残差へ流れ込む | #165 §2.2 が案B を棄却した理由（設計/製造を分離した四半期系列が存在しない）と同じ制約 |

## 2. なぜ企業開示を較正入力から除外するか

| 観点 | 内容 |
|---|---|
| 再現性 | 「主要 hyperscaler」の定義は時点により変わる。選定を固定しない集計は再現できない。[分析契約](../models/capex_credit_cycle_analysis_contract.md) §6 が「非公開企業・銀行データを前提とした較正」を対象外とした理由（再現不能な較正はリポジトリの再現性契約に反する）が、公開開示の集計にも同じ形で当てはまる |
| 概念対応 | 会計年度・セグメント区分・報告基準が企業間・時点間で一致しない。部門定義（`S1` = AI・クラウド需要）との対応が任意になる |
| 代替の有無 | `capex_exec_s1` は BEA NIPA の情報処理機器・ソフトウェア・構築物投資から構成できる（`C` 分類）。**CAPEX の実行額という最重要変数はマクロ統計で賄える** |
| 失うもの | `S1` の収益ブロックと `capex_plan_s1`。したがって「計画と実行の差」（`cancel_s1`・`capex_defer_s1`）と `R1a` は実証的に検証されない |
| 除外しない場合に起きること | 較正結果が企業選定に依存し、選定を変えると結論が変わる。その依存が metadata に残らないまま「実データで較正した」と報告される |
| 将来の解除条件 | 選定基準・集計規則をバージョン付きで固定できる企業データ provider が整備された場合。その時点で本書を改訂し `A` → `P` へ移す |

## 3. なぜ推定をブロック分割し、順序を固定するか

| 論点 | 決定 | 根拠 |
|---|---|---|
| 44 系統の同時推定 | 採らない | [ADR 0004](0004-keen-empirical-calibration-strategy.md) は Keen の 10 パラメータでさえ全同時推定を既定にしなかった。本モデルは観測系列数に対してパラメータ数が桁違いに多い |
| 分割の単位 | 因果グラフのブロック（金融条件・期待計画・生産在庫・価格・雇用・消費）に対応させる | [ADR 0011](0011-capex-credit-cycle-dynamics-contract.md) 決定 1 により期内に同時方程式が無く、各ブロックが逐次単一方程式として書けるため、分割が構造と整合する |
| 順序を固定する理由 | 逐次推定は前段の結果を所与とするため順序依存である。順序を実装者が選ぶと、結果の差が記録されないまま生じる | 「実装者が本書に無い判断を独自に行わない」という上流の規律（#165 §1.2-2・[動学方程式](../models/capex_credit_cycle_equations.md) §1.2-7）と同型 |
| 順序の決め方 | 観測が `D` 分類で揃うブロックを先に、潜在変数に依存するブロックを後に置く | `EB-3`（生産・在庫）は 5 系列すべてが `D` で、かつ在庫・受注残の会計恒等式が自由度を削るため最も識別が良い。`EB-2`（資本コスト・担保）は 4 本が原理的に識別できない |
| 系列が欠ける場合 | 推定せず `CAL-OBS` / `SENS` へ落とす | 欠損を補完して推定すると、補完方式が推定値へ影響する。§2.3 の「暗黙補完しない」規約の帰結 |

## 4. なぜ弱識別対応を事前規則化するか

| 対応 | 適用条件（事前） | 適用後の報告 |
|---|---|---|
| `W1` 固定へ降格 | 対応する観測変数が `E`（潜在）、または方程式の左辺が観測できない | 固定値と出典。推定を試みなかったことを明示 |
| `W2` 範囲報告 | 観測が `P` または `allocation` 依存で、proxy・按分キーの選択で推定値が動く | objective の等値域をグリッドで報告。点推定を出さない |
| `W3` 複数仕様併記 | 潜在系列の構成方式が複数ありうる（`ai_exp` の 3 仕様） | 仕様ごとの推定値を並べる。単一値を採らない |
| `W4` 感応度のみ | ブロックの観測が揃わない、または閾値パラメータ（`NL-1`–`NL-7`） | 既定値と走査範囲 |

**事後に選ばない理由**: 推定後に対応を選ぶと、「点推定が出たときは点推定、出なかったときは範囲」という選択自体が結果を良く見せる方向へ偏る。事前規則化は、弱識別が「検出された事実」として残ることを保証する。

**弱識別を理由に推定対象を増やさない理由**: 識別が難しい原因は自由度の不足ではなく観測情報の不足である。パラメータを追加しても情報は増えず、fit だけが改善する。

## 5. なぜ診断閾値と起点ショック規模を較正しないか

| 対象 | 較正しない理由 |
|---|---|
| `G1`–`G4` の深さ閾値・持続性 | [分析契約](../models/capex_credit_cycle_analysis_contract.md) §8-2 が「閾値は理論から導かれていない」と明記している。履歴再生で公式判定と一致するよう選ぶことは同 §4.1 が禁じる一致率の目的関数化に当たる |
| `breadth ≥ 0.60` | **原理的に較正できない**。実体部門 4 のため 0.25 刻みの離散値しか取らない（#165 §2.3）。`0.60` は「4 部門中 3 部門以上」を意味する |
| `SH-EXP` の規模 | 適用先 `ai_exp` が観測不能（`A`）である。観測に無い量の規模を「較正した」と述べることは [ADR 0010](0010-macro-event-scenario-contract.md) の magnitude 捏造禁止に触れる |
| 帰結 | `peak(dY)` の絶対的な大きさに実証的意味を与えられない。判定問題の回答は「どの条件で何が起きるか」に限られる |
| 代わりに行うこと | 閾値 ±50%（契約 §4.4 の義務）・`breadth` の 3 通り離散比較・`S1` 除外版の併記・ショック規模の走査 |

## 6. なぜ Q4 を履歴再生から外し、`A` を観測から計算しないか

| 論点 | 決定 | 根拠 |
|---|---|---|
| Q4（緩和による遮断） | 理論シナリオの反実仮想比較に限定 | モデルは政策反応関数を持たない（因果グラフ `X05` は `EXT`）。現実の緩和は内生反応であるため、実現値パスを外生入力として与えると緩和効果と自然回復が分離されない。分離できないまま「緩和が遮断した」と報告することが最も避けたい誤りである |
| `A`（増幅度） | 観測から計算しない | `A` は `credit-off` 反実仮想（信用感応パラメータを `0` に固定した同一実装の再実行）でのみ定義される。観測には反実仮想が存在しない |
| 履歴再生で行うこと | 信用条件が悪化した局面（`H2`・`H6`）と安定な局面（`H5`）で**モデルの `A` が異なるか**を報告する | モデル内の比較であり、観測の増幅の推定ではない |
| 他モデルとの比較で代用しないこと | [責務境界](../models/capex_credit_cycle_model_boundaries.md) §2.4 が既に禁じている（New Keynesian との IRF 差で代用しない） | 同名変数の非同一視（[ADR 0006](0006-cross-model-reasoning-contract.md)） |

## 理由

- **観測方程式の 9 項目化は、検出されない誤りを検出される誤りへ変える**。年率未換算・指数の水準扱い・部門範囲のずれは、metadata として記録されていれば会計検証・定常整合条件との交差確認で露出する。記録がなければ「実データで較正した」という申告だけが残る。
- **企業開示の除外は、較正の再現性を選定基準の固定という未解決問題から切り離す**。失うもの（`S1` 収益ブロック・`R1a` の検証）は明示的な限界として記録でき、得るもの（公開マクロ統計のみで完結する較正）は再現可能である。
- **ブロック分割と順序固定は、識別困難を「解いた」ふりをしない設計である**。[ADR 0011](0011-capex-credit-cycle-dynamics-contract.md) 決定 1 が期内の同時方程式を排したことにより、逐次単一方程式としての推定が構造的に正当化される。
- **弱識別対応の事前規則化は、報告の選択バイアスを構造的に防ぐ**。点推定が出たかどうかで報告形式を選べる余地を残さない。
- **診断閾値と起点ショック規模を較正しない決定は、判定問題の回答形式を限定する**。回答は「どの条件で何が起きるか」であり「どの程度悪化するか」ではない。この限定は契約 §3 の判定問題の書き方（真偽が一意に決まる関数）と整合する。
- **Q4 を履歴再生から外す決定は、最も誤用されやすい主張（政策が波及を止めた）を構造的に不可能にする**。契約 §4 Q4 の「政策提言・政策効果の因果推定として提示しない」を、実行構成のレベルで担保する。
- **4 レイヤー分離と単一 pass/fail の不採用は、[Keen 実証化戦略](../models/keen_empirical_strategy.md) §6.1 の検証層設計を継承する**。`calibrated_worse_than_literature` を隠さない方針も同じである。

## 見送りとした選択肢

- **全パラメータの同時推定**: 44 系統の行動パラメータを観測系列から同時推定する。識別可能性がなく、弱識別を検出しても報告形式が定まらない。
- **trajectory matching（軌跡全体の当てはめ）**: 非線形性 7 箇所と閾値（`NL-1`–`NL-7`）により目的関数が不連続になり、初期値依存・局所解の罠が生じる。[ADR 0004](0004-keen-empirical-calibration-strategy.md) が Keen の双安定性に対して同じ理由で棄却した。
- **企業開示の集計を較正入力に含める**: `capex_plan_s1`・`S1` 収益ブロックが観測に接続でき `R1a` を検証できるが、選定基準の固定という未解決問題を較正へ持ち込む。
- **履歴再生 baseline を実データのトレンドとする**: 観測の `dx_t` とモデルの `dx_t` の非対称性が解消するが、モデルが成長経路を持たないため定常条件（`SS-1`–`SS-17`）が満たされず、逆較正の前提が崩れる。
- **`breadth` 閾値の較正**: 実体部門 4 では 0.25 刻みしか取れず、較正の対象にならない。部門を分割して粒度を上げる案は #165 §2.3 が観測系列の不在を理由に棄却済み。
- **公式景気後退判定との一致率を目的関数にする**: 契約 §4.1 が禁じている。一致させると `broad_downturn` が NBER 判定の代理指標になり、モデル内診断ラベルという位置づけが崩れる。
- **`:as_of`（vintage）モードの初期実装**: 「その時点で判断できたか」を問えるようになるが、`DataSeries` に vintage 軸が無く、全必須系列（特に provider 経由の Census・BEA 系列）の vintage 取得経路が揃わない。部分的な vintage 対応を `:as_of` と称することは [シナリオ時間軸](../architecture/scenario_time_semantics.md) §6.3 の契約に反する。
- **`ext_demand_s` を残差ではなく独立に推定する**: 非 AI 半導体需要の系列（スマートフォン・自動車向け出荷）を別途構成する案。四半期・NAICS 粒度で分離した公表系列が無く、構成規則が残差以上に任意になる。
- **弱識別パラメータを追加の観測系列で識別する**: `cost_capital_s` の proxy（社債発行金利の加重平均等）を構成する案。proxy 定義に条件付きの識別であり、`W2`（範囲報告）と実質的に同じ情報しか得られないまま点推定に見える出力を生む。

## 影響

- **既存コードへの影響は無い**。本決定は設計文書の追加のみであり、`src/` 配下の変更を伴わない。
- **データ層実装** は決定 1–5・8–10 を満たす必要がある。既存 `FredClient`（fixture / live）と `to_quarterly(method=:mean|:sum|:end)`・`fill_missing` を再利用でき、`:end` 集計は実装済みである。provider 系列の取得経路と fixture 形式は #171 が確定する。
- **較正・推定層実装** は決定 10–16 を満たす必要がある。`steady_state_targets` と逆算パラメータの両方を保存する要件、推定ブロックの固定順序、`W1`–`W4` の事前割当が実装上の必須要件になる。
- **検証層実装** は決定 17–22 を満たす必要がある。Q4 を履歴再生から除外する構成、`A` を観測から計算しない構成、4 レイヤー分離の出力型が要件である。
- **LLM 説明層** は [観測方程式・識別戦略・検証方針](../models/capex_credit_cycle_empirical_strategy.md) §11 の限界 14 件を [llm_safety.md](../llm_safety.md) の必須記載事項および [動学方程式](../models/capex_credit_cycle_equations.md) §18 の必須記載 8 項目と併せて提示する。特に「その時点で予測できた」禁止（決定 8）・`P` 分類のずれの方向・`cost_capital_s` の単独提示抑止・`A` と `share_C` が反実仮想寄与であることを保持する。
- **#171（統合）** は §12 の引き渡し事項を受け取る。`:as_of` を実装しない決定の API 上の表現、初期状態指定 API と診断閾値セット型、methodology version 文字列の確定が対象である。
- **#164（因果グラフ）・#169（動学方程式）** への差し戻しは §7 の差し戻し候補に限る。本決定では差し戻しを行わない。
