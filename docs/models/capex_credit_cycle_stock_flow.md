## 1. 本書の位置づけと確定範囲

### 1.1 位置づけ

[分析契約](capex_credit_cycle_analysis_contract.md)が「何を問うか」、[因果グラフ](capex_credit_cycle_causal_graph.md)が「どの経路で伝わるか」、[部門境界と変数定義](capex_credit_cycle_sectors_variables.md)が「どの部門が何を持つか」を固定した。
本書はその上で「**各期の取引フローと期首・期末残高が会計的にどう閉じるか**」を固定する。

行動方程式（#169）を先に決めると、CAPEX 削減で消えた支出の行き先、銀行貸出の見合い、家計所得・消費・貯蓄、利払いと金融部門所得が不整合になる。本書はそれを防ぐため、**行動方程式が満たすべき制約の集合**を先に確定する。

| 本書が固定するもの | 本書が固定しないもの |
|---|---|
| 会計上の部門集合（`SX` の導入）・価値尺度・符号規約・時点規約・期内処理順序（§2） | 部門境界そのもの（#165 で確定済み） |
| 貸借対照表行列の行（金融商品）と符号（§3） | 各項目の水準・初期値（#170） |
| 取引フロー行列の行（取引種別）と相手部門（§4） | 部門間配分比の数値（#170） |
| 全ストックの残高更新式（§5） | 更新式に現れるフローを生成する行動方程式（#169） |
| CAPEX 資金調達恒等式と閉じ変数の指定（§6） | 資金調達順序の関数形・上限式（#169） |
| デフォルトの初期扱いと診断可能性の要件（§7） | 信用損失の内生化（将来拡張） |
| 自動テスト可能な会計恒等式・許容誤差・異常値の扱い（§8） | 検証層の Julia API 名・戻り値型（#171） |
| #99 Phase 5 SFC との責務境界（§9） | 完全な制度部門別 SFC の採否（#99 Phase 5） |

### 1.2 規律（契約）

1. **不整合を自動補正しない**。丸め・クリップ・辻褄合わせを行わず、違反は構造化して返す（[ADR 0007](../adr/0007-sfc-integration-contract.md) §5 と同型）。
2. **恒等式で決まる量を行動方程式で二重に決めない**。§5 の残高更新式・§4 の列和で決まる変数は、#169 が別途生成しない。
3. **残差で閉じない**。会計上の閉じ変数は §4.4・§6.2 で**明示的に指定した変数に限る**。指定のない差分が生じた場合は違反として検出する。
4. **初期MVPで省略する項目は、恒等的ゼロの独立項として保持する**（[ADR 0007](../adr/0007-sfc-integration-contract.md) §4 の `valuation_change ≡ 0` と同じ idiom）。項目自体を式から削除しない。
5. **`SX` 列の列和は定義上ゼロになるため、検証項目に含めない**。自明に成立する恒等式を検証に数えない（#165 の R-5 と同じ理由）。
6. **#165 の変数辞書に無い変数を本書で暗黙に追加しない**。追加が必要なものは §10.1 に**改訂提案として列挙**し、#165 の改訂で正式化する。

## 2. 会計の基本規約

### 2.1 会計上の部門集合

#165 が確定した 5 部門は、実物・金融フローの**相手方がすべてモデル内に存在するわけではない**。中間投入の供給元、法人税・家計税の受取先、モデル外需要（`ext_demand_s`）の発注元、`S4` の資金調達元、`S5` の貯蓄の行き先は、いずれもモデル外にある。

**決定**: 会計表の列に**モデル外・残差部門 `SX`** を追加する。

| ID | 名称 | 内容 |
|---|---|---|
| `SX` | モデル外・残差部門 | 政府・海外・非モデル化金融部門・非モデル化企業・統計上の残差を束ねた**会計上の対応部門**。経済主体としての行動方程式を持たない |

**契約**:

- `SX` は**会計部門であって経済部門ではない**。`SR`（契約 §4.2 の `breadth` の分母）に含めない。`SimulationResult` へ `SX` の産出・雇用を出力しない。
- `SX` へ帰属させるフローは §4 の行に**個別の取引項目として明示する**。「その他」でまとめない。
- `SX` の列和は定義上ゼロになるため検証対象にしない（§1.2-5）。代わりに、`SX` へ流れる各項目の**水準と `y_tot` 比**を診断量として出力し、規模が想定を超えた場合に警告する（§8.3）。
- `S4` の資金調達元・`S5` の貯蓄先を `SX` に置くことは、**銀行の資金制約と家計の資産蓄積を初期MVPで表現しないという設計判断**である。帰結は §12-1・§12-2 に記す。

### 2.2 価値尺度（numeraire）と実質/名目

#165 §5.1 は「実質、10 億ドル（2017 年連鎖ドル基準）」を規約とし、同時に `sales_s = price_s × y_s`（`price_s` は基準 1.0 の指数）を定めている。会計表は異なる部門のフローを**加算**するため、価値尺度を明示する必要がある。

**決定**: 会計表は**一般物価を数値基準（numeraire）とする実質価値額建て**とする。

| 項目 | 規約 |
|---|---|
| 数値基準 | 一般物価水準（GDP デフレータ相当）。モデル内で内生化しない |
| `price_s` の意味 | 一般物価に対する**相対価格**（baseline 定常で `1.0`） |
| 加算可能性 | すべての価値額は同一の数値基準で測られるため、部門横断で加算できる |
| 実質数量との関係 | `y_s`（10億ドル/四半期）は baseline 価格で評価した実質数量。価値額は `price_s × y_s` |
| `wage` の換算 | `wage`（指数）× `emp_s`（百万人）は価値額にならない。賃金支払額は `wagebill_s = st_wbase_s · wage · emp_s` で換算する（`st_wbase_s` †: 10億ドル/四半期/百万人、§10.1） |
| 金利 | `policy_rate`・`spread` は年率 %・bp。四半期の利払いには `Δt = 0.25` を掛けて換算する（§5.4） |

**契約**: 価格変動による**ストックの評価差額**は、初期MVPで `valchg` として恒等的ゼロの独立項として保持する（§5.7）。在庫・資本ストックは取得時価値で保持し、`price_s` の変動で再評価しない。

### 2.3 符号規約

既存 SFC 実装（[SFC 統合設計](sfc_integration_design.md) §3.2・§3.3、`:source_use`）と同一にする。**本モデル専用の符号規約を作らない**。

| 行列 | 規約 |
|---|---|
| 貸借対照表行列 | 行 = 金融商品・実物資産、列 = 部門。**資産 = 正、負債 = 負**。期末ストック。純資産行は各列の資産合計の符号反転 |
| 取引フロー行列 | 行 = 取引種別、列 = 部門。**資金の源泉（source）= 正、資金の使途（use）= 負**。期中フロー |

**注意**: `:source_use` 規約では、資産の増加（現金を積む）は資金の**使途**なので負、負債の増加（借りる）は資金の**源泉**なので正になる。したがってストック変化と取引フローの符号は逆になり、ストック・フロー整合式の残差は `Δstock + flow − valuation` で評価する（[SFC 統合設計](sfc_integration_design.md) §5.3 と同一）。

### 2.4 時点規約

| 概念 | 記号 | 規約 |
|---|---|---|
| 期首（`BOP`） | `x[t−1]` | 前期末残高と同一。**新たな時点を設けない** |
| 期中フロー（`SUM`） | `x` | 四半期合計。年率換算しない |
| 期末（`EOP`） | `x` | すべてのストックは期末値で保持する（#165 §5.1 を継承） |
| レート・比率（`AVG`） | `x` | 四半期平均。ただし当期フロー同士の比（`coverage_s`・`margin_s`）は四半期値そのもの |

**契約**:

- **意思決定はすべて期首ストックを参照する**。当期末ストックを当期の意思決定へ入力しない。`util_s = y_s / ycap_s[t−1]`†、`int_burden_s = r_eff_s · Δt · debt_s[t−1]`、`matur_s = φ_s · debt_s[t−1]` はいずれも期首基準である。
- **当期の資金制約は期首現金 `cash_s[t−1]` と前期営業CF `ocf_s[t−1]` で評価する**（§2.5 ステップ 4）。当期 `ocf_s` は当期の生産・販売の結果として後段で決まるため、資金制約へ入れると同時決定になる。因果グラフ `L41`（`CASH_s → CAPEX_EXEC`、遅れ `0–1`）の遅れを **`1` に確定**する。`0` を採る場合は同時方程式の解法が必要になるため、#169 が採用する場合は本書を改訂する。

### 2.5 期内処理順序

会計が閉じるためには、各期の変数決定順序が一意でなければならない。次の順序を固定する。

| # | ステップ | 決まる主な量 | 参照する時点 |
|---|---|---|---|
| 1 | 外生入力の適用 | `ai_exp`・`policy_rate`・`spread_shock_ex`・`capex_plan_shock_ex`・`ext_demand_s` | — |
| 2 | 金融条件の決定 | `fin_cond`・`spread`・`lend_stance`・`rollover`・`cost_capital_s`・`r_eff_s`† | 期首ストック・前期内生値 |
| 3 | 計画 | `compute_dem`・`target_cap_s1`・`capex_plan_eff_s1`†・`invest_s` の計画値 | 期首 `cap_s`・`plan_carry_s1`† |
| 4 | 資金制約と実行 | `matur_s`†・`refin_s`†・`newdebt_s`†・`repay_s`†・`equity_issue_s`†・`capex_cancel_s1`†・`capex_defer_s1`†・`capex_exec_s1`・`invest_s` | 期首 `cash_s`・`debt_s`、前期 `ocf_s` |
| 5 | 受注配分 | `order_s`（`L09`・`L19`・`L50`・`ext_demand_s` の合成） | 当期 `capex_exec_s1`・`invest_s`、前期 `y_s5` |
| 6 | 生産・出荷 | `y_s`・`ship_s`†・`util_s`・`price_s` | 期首 `cap_s`・`backlog_s`・`inv_s` |
| 7 | 所得・支出 | `emp_s`・`wage`・`wagebill_s`†・`hh_income`・`cons`・`y_s5` | 当期 `y_s`・`capex_exec_s1` |
| 8 | 収益・分配 | `sales_s`・`im_s`†・`dep_s`†・`profit_s`・`int_burden_s`・`tax_s`†・`div_s`†・`ocf_s` | 当期フロー、期首 `debt_s` |
| 9 | 残高更新 | すべてのストック（§5） | 期首ストック + 当期フロー |
| 10 | 会計検証・診断 | §8 の恒等式、契約 §4 の診断ラベル | 期首・期末・当期フロー |

**契約**: ステップ 4 が 6・8 より前にあることが、§6 の資金調達恒等式が**事前制約**として働くための条件である。実行 CAPEX を先に決めてから事後的に資金を割り当てる順序にしない。#169 はこの順序を変更しない。

| 現金・預金 `deposit` | `+cash_s1` | `+cash_s2` | `+cash_s3` | `−Σ cash_s` | `0` | `0` | **`0`** |
| 貸出・社債 `loan` | `−debt_s1` | `−debt_s2` | `−debt_s3` | `+Σ debt_s` | `0` | `0` | **`0`** |
| 前受金・前渡金 `advance` | `+adv_{S1}` | `+adv_{S2}` `−advance_s2` | `−advance_s3` | `0` | `0` | `0` | **`0`**（MVP は全ゼロ） |
| モデル外調達 `extfund` | `0` | `0` | `0` | `−fund_s4` | `0` | `+fund_s4` | **`0`** |
| 純資産 `balance` | `−nw_s1` | `−nw_s2` | `−nw_s3` | `−nw_s4` | `0` | `−nw_sx` | `−Σ 実物資産` |
| Σ（列和） | `0` | `0` | `0` | `0` | `0` | `0` | `0` |

**読み方**

- **金融商品行の行和 = 0**（`deposit`・`loan`・`advance`・`extfund`）。すべての金融資産は誰かの負債である。この 4 行が §8 の `:balance_row_sum` の検証対象である（`advance` は MVP では全ゼロだが、行を削除せず独立に保持する。§1.2-4）。
- **実物資産行の行和 ≠ 0**（`cap`・`cip`・`inventory`）。実物資産には対応する負債が存在しないため、行和は経済全体の実物資産残高になる。**この 3 行を `:balance_row_sum` の検証対象に含めない**。
- **純資産行を含めた列和 = 0**（`:balance_column_sum`）。
- `S5` 列は全行ゼロである。これは #165 §3.5 の設計判断（家計は金融資産・負債を持たない）の帰結であり、**`S5` の純資産を追跡しないこと**を意味する（§12-2）。
- `adv_{S1}`・`adv_{S2}` は買い手側の前渡金保有額。初期MVPでは発注・引渡・支払を同一期に置くため全ゼロである（§4.4）。

### 3.3 `S4` の貸借対照表と純資産の扱い

#165 §3.4 は「初期MVPでは `S4` 側の貸借対照表を独立に持たず、`debt_s` の反対側として扱う。完全な複式計上は #166 が決める」とした。

**決定**: `S4` の貸借対照表を明示的に持ち、**純資産を恒等的ゼロとする**。

```
資産  : loans_s4  = Σ_{s∈SF} debt_s
負債  : deposits  = Σ_{s∈SF} cash_s
        fund_s4   = loans_s4 − Σ_{s∈SF} cash_s     … モデル外からの調達（残差）
純資産: nw_s4     ≡ 0
```

**根拠**

1. `S4` の与信は `debt_s` の反対側として一意に決まるため、資産側に独立の自由度は無い。
2. 銀行の資金調達を**完全弾力的**（`fund_s4` が必要額だけ受動的に調整される）とすることで、`S4` の資金制約が信用供給を制約しない構造になる。初期MVPの信用収縮は**価格・条件**（`spread`・`lend_stance`・`rollover`）のみで表現し、**数量制約**（貸出可能額の上限）は表現しない。これは因果グラフのブロック D（`L36`–`L42`）が価格・条件経路のみを持つことと整合する。
3. `nw_s4 ≡ 0` とすることで、`S4` の利子収入は当期に全額 `SX` へ移転される（§4.3 の `F-09`）。`S4` の利益・自己資本・貸倒吸収能力を持たないため、**信用損失の内生化には `nw_s4` の導入が前提になる**（§7.2）。

**契約**: `fund_s4` は残差として定義されるため、`S4` の列和は自明にゼロになる。**`S4` 列を `:flow_column_sum` の検証対象に含めない**（§8.1）。代わりに `:s4_balance_sheet` として `loans_s4 = Σ debt_s` と `deposits = Σ cash_s` を独立に検証する。

### 3.4 株式を貸借対照表へ載せない決定

| 検討 | 内容 |
|---|---|
| **決定** | 株式（`:equity`）を初期MVPの貸借対照表行列に**行として持たない**。`equity_val` は市場評価の指数であり、いかなる部門の資産・負債としても計上しない |
| **根拠 1** | `equity_val` は指数（基準 1.0）であり価値額ではない。時価総額へ換算する構造パラメータを置くと、その水準が `nw_s` と乖離したときの調整項（のれん・評価差額）が必要になり、初期MVPで識別できない自由度が増える |
| **根拠 2** | 株式を時価で負債側に載せると、株価下落が発行体の純資産を**増加**させる（負債の時価減）。これは因果グラフ §6.1 の禁止（株価から実体への直接作用）と矛盾する解釈を誘発する |
| **根拠 3** | 保有者は `SX`（家計は金融資産を持たない）であり、`SX` の純資産変動は追跡しないため、株式を載せても検証力のある恒等式が増えない |
| **帰結** | 増資 `equity_issue_s`† は**フローとしてのみ**存在し、`nw_s` を直接増加させる（§5.6）。株式の残高は持たない |
| **将来拡張** | 家計の金融資産（`X01` 資産効果）を導入する際に、株式を instrument として追加する。その時点で `nw_s` と時価の乖離をどう扱うかを決める |

### 3.5 `capex_pipe_s` の内容と引渡ラグの所在

初期MVPでは、資本財の**発注・引渡・支払を同一期**に置く（§4.4）。したがって `capex_pipe_s`（建設中CAPEX残高）に計上されるのは次の 1 種類のみである。

```
capex_pipe_s = 引渡済み・未稼働の資本財（建設中・据付中を含む）
```

- 買い手は発注＝引渡の当期に支払い、`capex_pipe_s` が増加する。
- 稼働開始時に `capex_pipe_s` から `cap_s` へ振り替わる（`capstart_s`†、§5.2）。この振替までの遅れが因果グラフ `L08`・`L57` の遅れ `2–4` である。
- **引渡までのラグと据付・建設のラグを区別せず、両方を `capex_pipe_s` の滞留として表現する**。前渡金 `advance_s` を持たないのはこのためである。

**MVP 仮定 A-2（資本財需要の充足）**: `S1`・`S2` の資本財需要は当期に全額引き渡される。受注残 `backlog_s` に滞留するのは一般需要・モデル外需要の未充足分である。この仮定により、`capex_exec_s1` は `S1` の意思決定変数として保たれる（売り手の出荷能力によって買い手の支出が決まる構造にならない）。

**A-2 を緩める場合の拡張経路**: 資本財の納期遅延を表現する場合、`advance_s`（前受金・前渡金）に値を入れる。売り手の負債 `advance_s = price_s · backlog_s^{cap}`、買い手の資産 `adv_{b,s}` として計上し、`capex_pipe_s` は「前渡金 + 引渡済未稼働」の 2 内訳になる。§3.1・§3.2 に行を保持しているのは、この拡張で行列の形を変えないためである。

## 4. 取引フロー行列

### 4.1 構成

取引フロー行列を **2 ブロック**に分ける。ブロックの境界に**資金過不足（純貸出/純借入）`nlb_s`†** を置く。

| ブロック | 内容 | 列和 |
|---|---|---|
| **経常・資本ブロック**（`C-*`） | 財・サービス取引、賃金、利払い、税、配当、資本形成 | `= nlb_s` |
| **金融ブロック**（`F-*`） | 現金・債務・前受金・モデル外調達の増減、増資 | `= −nlb_s` |
| 合計 | — | **`0`**（部門予算制約） |

`nlb_s` は「経常・資本取引の結果として、その部門が正味で資金を供給したか（正）・調達したか（負）」を表す。§8 の `:nlb_consistency` は、2 ブロックの列和が符号反転で一致することを検証する。

- **すべての行の行和が 0 になる**。実物投資は買い手の列に使途として現れ、同時に売り手の列に源泉として現れるため、独立の「固定資本形成」行を持たない（単一列方式）。減価償却は取引ではないため行を持たない（§4.5）。
- `C-01`: `sales_s1 = price_s1 · y_s1`。買い手は `S5`（`cons_s1` = 家計消費と `S5` 企業の IT 支出の合計）と `SX`（モデル外需要 `xsales_s1`）。`y_s1` の生成方程式は #165 §7 の差し戻し `A1` が未解決のため、`A1` 解決までは `cons_s1 ≡ 0`・`xsales_s1 = sales_s1` として `SX` へ全額帰属させる暫定運用とする（§10.2 の `B4`）。
- `C-02`・`C-03`: 売り手の**産出額** `sales_s = price_s · y_s`（在庫品増加を含む）を源泉に立て、買い手の購入 `d_{b,s}`† と自己勘定の在庫品増加 `dinv_s`† を使途に立てる。`Σ_b d_{b,s} + dinv_s = sales_s` が行和ゼロの内容であり、`Σ_b d_{b,s} = deliv_s = price_s · ship_s` である（§5.3 の `inv_s` 更新式と整合）。
- **買い手側の資本形成の分解**（#165 の集計規約 R-3・R-4 に対応、§8.1 の `:no_double_count`）:

  ```
  capex_exec_s1 = d_{S1,S2} + d_{S1,S3} + capex_sx_s1          （R-3）
  invest_s2     = d_{S2,S3} + inv_sx_s2                         （R-4）
  invest_s3     = inv_sx_s3                                     （X06 が EXT のため相手は SX のみ）
  ```

- `C-04`: `sales_s5 = y_s5`（`S5` に相対価格を置かないため数量＝価値額）。買い手は `S5` 自身（家計消費のうち自部門向け `cons_s5`†）と `SX`（`xdem_s5`† = `S5` の産出のうち家計消費以外の需要。政府支出・純輸出・非 AI 企業投資を含む）。`cons = cons_s1 + cons_s5` である。
- `C-05`: モデル内部門間の財のやり取りは資本財と最終需要（`C-01`–`C-04`）に限り、中間投入はすべて `SX` から購入する。これは #165 の集計規約 R-2（受注・受注残・在庫は総額ベース、部門横断で合計しない）と整合する。`capex_sx_s1`†・`inv_sx_s`† はモデル外から調達する資本財（土地・輸入設備等）である。
- **付加価値と利益の関係**: `im_s = (1 − st_va_share_s) · sales_s`（#165 の R-1 の `va_share_s` を産出額ベースで用いる）、`va_s = sales_s − im_s`、そして

  ```
  profit_s = va_s − wagebill_s − dep_s          … 利益は会計残差
  ```

  **`profit_s` を行動方程式で独立に生成しない**。因果グラフ `L22`（`SALES_s → PROFIT_s`、型 `行動`、固定費レバレッジ）が表す非線形性は、`wagebill_s`（労働退蔵により産出に対して固定的）と `dep_s`（完全固定費）の性質から**導出される**ものであり、利益を売上の関数として別に置くと `C-02`・`C-06` と矛盾する。`L22` の型を `会計` へ変更する提案を差し戻し `B6`（§10.2）として登録する。
- `C-06`: `S5` の列は家計と非 AI 企業を合算しているため、`S5` 内部の賃金支払（`wagebill_s5`）は列内で相殺される。行列には計上しない（§4.5）。`S5` が受け取るのは `S1`–`S3` からの賃金のみである。
- `C-09`・`C-10`: `S4` は利子収入を全額 `SX` へ移転する（`nw_s4 ≡ 0`、§3.3）。`S4` の費用・雇用・利益を持たない #165 §3.4 の設定を会計的に閉じる措置である。

### 4.4 計上基準の決定

| 対象 | 決定 |
|---|---|
| **売り手の収益認識** | **産出（生産）基準**。`sales_s = price_s · y_s` は在庫品増加を含む**産出額**である（#165 の `L20`・`L21` の定義を維持する） |
| **買い手の支出計上・現金の受渡し** | **引渡基準**。買い手の支払と売り手の受取は引渡時に生じ、金額は `deliv_s = price_s · ship_s`† である |
| **資本財の発注・引渡・支払** | **同一期**に置く（仮定 A-2、§3.5）。発注から引渡までのラグは、買い手側の `capex_pipe_s`（稼働開始までの滞留）に集約する |
| **前受金・前渡金** | `advance_s ≡ 0`（独立項として保持、§3.5 の拡張経路） |

**根拠**

1. `capex_exec_s1` は `S1` の**意思決定変数**（役割 `control`、#165 §4.4）である。仮定 A-2 により、売り手の出荷能力が買い手の支出を決める構造を避ける。
2. 収益認識を産出基準に置くのは #165 が `sales_s = price_s × y_s` を確定しているためである。在庫品増加は自己勘定投資として同一行に計上され（`C-02`・`C-03`）、二重計上にならない。
3. 発注・引渡・支払を同一期に置いても、**資本財が稼働するまでの遅れは失われない**。因果グラフ `L08`・`L57` の遅れ `2–4` は `capex_pipe_s` の滞留として保持される。

この決定により、**営業CFと運転資本の関係**が次のように閉じる。

```
Δwc_s  = Δinvval_s                                              … 運転資本＝在庫（前受金 ≡ 0）
ocf_s  = profit_s + dep_s − Δwc_s                                （s ∈ SP）
       = price_s · ship_s − im_s − wagebill_s                    （現金ベースの再掲）
ocf_s1 = profit_s1 + dep_s1                                       （Δwc_s1 ≡ 0、在庫を持たない）
```

**現金ベースとの一致の確認**: `profit_s = sales_s − im_s − wagebill_s − dep_s` かつ `Δinvval_s = price_s · (y_s − ship_s)` より、
`ocf_s = price_s · y_s − im_s − wagebill_s − price_s · (y_s − ship_s) = price_s · ship_s − im_s − wagebill_s`。すなわち**在庫の積み上がりはその分だけ営業CFを減らす**。これが因果グラフ `L23`（`PROFIT_s → OCF_s`、運転資本調整付き）の会計的内容である。

**限界**: 分割払い・納期遅延・売掛買掛の条件を表現しない。#164 の `CAPEX_EXEC` が発注ベースか引渡ベースかは明示されておらず、また `L09`（`CAPEX_EXEC → ORDER_s`）と仮定 A-2 の関係も未確定であるため、差し戻し `B3`（§10.2）として登録する。

**契約**: `ocf_s` は**利払い前・税引前**とする。#165 の `coverage_s = ocf_s / int_burden_s` が「営業CFが利払いをどれだけ上回るか」を意味するためであり、[Minsky 資金調達区分診断](minsky_regime_diagnostics.md) §2 の `π = 営業余剰 − 利払い` と同じ層で定義される。`ocf_s` を利払い後で定義すると `coverage_s` の解釈が壊れる。

### 4.5 部門内取引・実物投資の扱いと `S5` の閉じ変数

行和がゼロにならない行、および列内で相殺される取引の扱いを明示する。

| 対象 | 扱い | 理由 |
|---|---|---|
| 固定資本形成の独立行 | **持たない**。買い手の資本財購入は `C-02`・`C-03`・`C-05` の使途として一度だけ現れる | 単一列方式では、買い手の投資支出と売り手の販売が同一行の両側になる。独立の投資行を立てると二重計上になる |
| 固定資本減耗 | **取引行を持たない**。`dep_s` は `profit_s` の算出に用いる会計上の控除であり、部門間の資金移動を伴わない | 取引フロー行列は資金の移動を記録する。減価償却は非現金項目であり、列和（`nlb_s` = 総貯蓄 − 総投資）は総額ベースで自動的に整合する |
| 在庫品増加 | `C-02`・`C-03` の**売り手列の使途**として計上する（`−dinv_s`） | 産出額 `sales_s` に在庫品増加が含まれるため、対応する使途を同一行に立てないと行和が 0 にならない |
| `C-04` `S5` 内部の消費 | `cons_s5` として**明示的に計上する**（同一列内の源泉と使途） | 列内で相殺されるが、明示することで `cons = cons_s1 + cons_s5` の分解と `xdem_s5` の残差が追跡可能になる |
| `C-06` `S5` 内部の賃金 | **計上しない**。`S5` は家計と非 AI 企業を合算した部門である（#165 §3.5） | 内部取引を明示すると、存在しない部門境界を仮定することになる。`S5` が受け取るのは `S1`–`S3` からの賃金のみ |
| `S5` 列の閉じ変数 | `C-12` の **`s5_net_sx` のみ**。金融ブロックが全ゼロであるため `nlb_s5 ≡ 0` が成立する | `S5` は金融資産・負債を持たない（#165 §3.5）ため、資金過不足がゼロでなければならない。`s5_net_sx` は家計貯蓄 `hh_income − cons` と非 AI 企業の余剰の合計に等しい |
| `SX` 列 | 定義上すべてを吸収するため列和は自明にゼロ。**検証対象にしない** | §1.2-5 |

**`S5` 残差の監視契約**: `s5_net_sx` は `y_s5`・`cons`・`hh_income` が**独立の行動方程式で生成される**ため、真の残差である。定義上は

```
s5_net_sx = Σ_{s∈{S1,S2,S3}} wagebill_s + sales_s5 − cons_s5 − cons_s1 − im_s5 − tax_hh
            − d_{S5,S2} − d_{S5,S3} − xdem_s5
```

であり、`xdem_s5`（`S5` 産出のうち家計消費以外の需要）を独立に生成するか残差として逆算するかで性質が変わる。**`xdem_s5` を残差として逆算しない**（#165 の R-5 と同じ理由）。`|s5_net_sx| / y_tot` を診断量として毎期出力し、既定閾値 `0.05` を超えた期を `acc_warning` として報告する（§8.3）。閾値超過を自動補正しない。これは `S5` 集約の弱点を隠さないための措置である。

## 5. 残高更新式

すべてのストックは期末値（`EOP`）である。`x[t−1]` は期首（前期末）。#165 §4.2 が役割 `state` と判定した 16 変数に加え、本書が追加提案する状態変数（§10.1）を対象とする。

### 5.1 稼働資本ストック

```
cap_s = cap_s[t−1] + capstart_s − dep_s − retire_s          （s ∈ {S1, S2, S3}）
dep_s    = st_delta_s · cap_s[t−1]                          … 固定資本減耗（取引行を持たない、§4.5）
retire_s ≡ 0                                                … 除却（MVP、独立項）
```

- `capstart_s`†（稼働開始額）は `capex_pipe_s` からの流出であり、因果グラフ `L08`（`S1`）・`L57`（`s ∈ SP`）の「遅れ `2–4`」を担う。#169 は `capstart_s` の生成規則（固定ラグ・幾何ラグ等）を選ぶが、**`capex_pipe_s` を経由しない資本増加を作らない**。
- 除却 `retire_s` は減耗に統合し、MVP では恒等的ゼロとする。設備の陳腐化（因果グラフ `B4` の「他用途需要への設備転用」の反対側）を明示的に扱う場合はここに値を入れる。
- **単位の注意**: `cap_s`（`s ∈ SP`）は #165 で「10億ドル/四半期（生産能力）」と定義されているが、貸借対照表の資産として加算するには「10億ドル（資本ストック）」でなければならない。本書は `cap_s` を**資本ストック**とし、生産能力を `ycap_s = cap_s / st_cor_s`†（`st_cor_s` = 資本産出比率、四半期）として分離する。`util_s = y_s / ycap_s[t−1]` となる。差し戻し `B1`（§10.2）。

### 5.2 建設中資本（パイプライン）

```
capex_pipe_s1 = capex_pipe_s1[t−1] + capex_exec_s1 − capstart_s1 − pipe_cancel_s1
capex_pipe_s  = capex_pipe_s[t−1]  + invest_s      − capstart_s  − pipe_cancel_s     （s ∈ SP）
pipe_cancel_s ≡ 0                                  … 着工済み案件の取消（MVP、独立項）
```

- `pipe_cancel_s`†（着工済み案件の取消）を恒等的ゼロとすることは、**因果グラフ `B3`（CAPEX の不可逆性）を「完全不可逆」として実装する**ことを意味する。#169 が部分不可逆を導入する場合は `pipe_cancel_s ≤ (1 − st_irrev_s) · capex_pipe_s[t−1]`† の形で上限を与える。
- **計画段階のキャンセル（`cancel_s1`）と着工後の取消（`pipe_cancel_s1`）は別物である**。前者は貸借対照表に一切現れない（計画は資産ではない）。後者は建設仮勘定の除却損として純資産を減らす（§5.6）。この区別が §6 の資金調達恒等式で本質的になる。

### 5.3 在庫・受注残・繰越計画

```
inv_s     = inv_s[t−1]     + y_s     − ship_s                （s ∈ SP）
backlog_s = backlog_s[t−1] + order_s − ship_s                （s ∈ SP）
invval_s  = st_invprice_s · inv_s                            … 在庫の価値額（取得時価格で評価）
plan_carry_s1 = plan_carry_s1[t−1] + capex_defer_s1 − （当期に復活した繰越分）
```

- `ship_s`†（出荷＝需要充足量）は #165 の表 B が「出荷」として言及しながら変数化していない量である（差し戻し `B2`）。在庫と受注残の**双方**を同一の `ship_s` で減じることが、`L12`（`Y_s → BACKLOG_s`）と `L14`（`ORDER_s → INV_s`）の会計的整合の条件である。
- `invval_s` は取得時価格 `st_invprice_s`† で評価し、`price_s` の変動で再評価しない（§2.2）。評価差額は §5.7 の `valchg` に独立項として保持する。
- `plan_carry_s1`†（繰越計画残高）は延期された CAPEX 計画の在庫である。**資産ではないため貸借対照表に載せない**。計画の状態変数として保持する（§6.2）。

### 5.4 現金・債務・実効金利

```
cash_s = cash_s[t−1] + ocf_s − int_burden_s − tax_s − div_s − I_s
                     + newdebt_s − repay_s + equity_issue_s                      （s ∈ SF）
   ただし I_s = capex_exec_s1（s = S1）/ invest_s（s ∈ SP）

debt_s = debt_s[t−1] + newdebt_s − repay_s − writeoff_s                          （s ∈ SF）

matur_s = φ_s · debt_s[t−1] ,       φ_s = Δt / st_maturity_s = 0.25 / st_maturity_s
refin_s = rollover · matur_s                                    … 借換実行額（0 ≤ refin_s ≤ matur_s）
repay_s = matur_s − refin_s                                     … 現金による純元本返済

int_burden_s = r_eff_s · Δt · debt_s[t−1]
r_eff_s      = (1 − φ_s) · r_eff_s[t−1] + φ_s · r_new_s         … 実効金利（状態変数）
r_new_s      = (policy_rate + spread / 100) / 100               … 借換・新規調達に適用される年率
```

- **`debt_s` の更新に借換 `refin_s` は現れない**。借換は満期到来分の置換であり残高を変えないためである。この分離により、「借換できなかった額」`repay_s = (1 − rollover) · matur_s` が**現金流出として明示的に現れる**。因果グラフ `L32`（`COLLATERAL → ROLLOVER`）→ `L40`（`ROLLOVER → CAPEX_EXEC`）の作用が、資本コストとは独立な**現金制約**として会計に入る（§6.4）。
- `r_eff_s`†（実効金利）は前期の自身の値を参照するため、#165 §4.2 の判定規則 3 により役割は **`state`** である。#165 は `int_burden_s` を `diagnostic` としており、その根拠（「前期末 `debt` を参照するが自身の前期値は参照しない」）は `r_eff_s` を状態として分離すれば維持される。平均満期 `st_maturity_s` による幾何的な満期到来を仮定する。
- **元本返済の代理仮定について**: #165 は `debt_service_s` の元本返済代理仮定を [Minsky 資金調達区分診断](minsky_regime_diagnostics.md) の方式（`amortization_rate` という診断層の仮定）を参照して #166 で確定するよう求めた。**本モデルでは満期構成 `st_maturity_s` からモデル内フロー `matur_s` を明示的に生成するため、診断層の代理仮定を用いない**。`debt_service_s = int_burden_s + repay_s` はモデル内の実際の現金支払である。Keen 側との非同一性は §7.4。

### 5.5 前受金・金融部門・家計

```
advance_s ≡ 0                                                           （s ∈ SP、MVP。§3.5 の拡張時は
                                                                         advance_s = price_s · backlog_s^{cap}）

loans_s4  = loans_s4[t−1]  + Σ_{s∈SF} (newdebt_s − repay_s − writeoff_s)   ＝ Σ debt_s
dep_s4    = dep_s4[t−1]    + Σ_{s∈SF} Δcash_s                              ＝ Σ cash_s
fund_s4   = loans_s4 − dep_s4                                              … 残差、nw_s4 ≡ 0

s5_net_sx = hh_income − cons + （S5 企業の余剰）                            … S5 の純流出（残高を持たない）
```

- `loans_s4`・`dep_s4` は**独立の状態変数ではない**（`Σ debt_s`・`Σ cash_s` に一致する）。役割は `diagnostic` とし、一致を §8 の `:s4_balance_sheet` で検証する。この重複は冗長ではなく、`S4` 側の集計と借り手側の残高更新が独立に計算されることで**検出力のある検証**になる。
- `s5_net_sx` は残高を蓄積しない（§3.2 の `S5` 列が全ゼロ）。家計・非 AI 企業の純資産を追跡しないという設計判断の帰結である（§12-2）。

### 5.6 純資産

純資産は資産・負債から導出される（役割 `diagnostic`）。

```
nw_s = cap_s + capex_pipe_s + invval_s + cash_s − debt_s          （s ∈ SF）
nw_s4 ≡ 0
```

§5.1–§5.5 の更新式から、純資産の変化について次が**導出**される。

```
Δnw_s = profit_s − int_burden_s − tax_s − div_s        … 内部留保
        + equity_issue_s                                … 増資
        + writeoff_s                                    … 債務免除益
        − retire_s − pipe_cancel_s                      … 除却損・建設中案件の取消損
        + valchg_s                                      … 評価差額（MVP ≡ 0）
```

**導出**（`Δwc_s = Δinvval_s`、`ocf_s = profit_s + dep_s − Δinvval_s`、`dep_s = st_delta_s · cap_s[t−1]` を用いる）:

```
ΔA_s  = (capstart_s − dep_s − retire_s) + (I_s − capstart_s − pipe_cancel_s) + Δinvval_s + Δcash_s
Δcash_s = ocf_s − int_burden_s − tax_s − div_s − I_s + newdebt_s − repay_s + equity_issue_s
ΔL_s  = newdebt_s − repay_s − writeoff_s

Δnw_s = ΔA_s − ΔL_s
      = −dep_s − retire_s − pipe_cancel_s + Δinvval_s
        + ocf_s − int_burden_s − tax_s − div_s + equity_issue_s + writeoff_s
      = −dep_s − retire_s − pipe_cancel_s + Δinvval_s
        + (profit_s + dep_s − Δinvval_s) − int_burden_s − tax_s − div_s + equity_issue_s + writeoff_s
      = profit_s − int_burden_s − tax_s − div_s + equity_issue_s + writeoff_s − retire_s − pipe_cancel_s
```

`capstart_s`（パイプラインから資本へ）と `I_s`（現金から資本形成へ）が相殺し、`dep_s` と `Δinvval_s` も相殺する。残るのは**内部留保・増資・債務免除益・除却損・取消損**のみである。

**契約**: この式は**残高更新式ではなく検証恒等式**である（`nw_s` は導出量であり独立の状態を持たない）。§8 の `:net_worth_update` として自動テストする。左辺（資産・負債から導出）と右辺（フローから構成）を独立に計算して比較することで、§5.1–§5.5 のいずれかの更新式の誤りを検出できる。

**株価が現れないことの確認**: 上式に `equity_val`・`collateral` は現れない。株式評価の変動は**いかなる部門の純資産にも直接影響しない**（§3.4・§6.4）。

### 5.7 評価差額の独立項

```
valchg_s ≡ 0        （初期MVP）
```

在庫の価格変動による評価差額、資本ストックの再評価、株式・債券の時価変動をすべて `valchg_s` に集約し、初期MVPでは恒等的ゼロとする。ストック・フロー整合式には**独立項として明示保持**する（[ADR 0007](../adr/0007-sfc-integration-contract.md) §4 の `valuation_change ≡ 0` と同一の idiom）。

```
stock_t − stock_{t−1} = transaction_flow_t + valuation_change_t
```

これにより、将来の価格評価・複数金融商品の導入時に、恒等式の形を変えずに値を入れるだけで拡張できる。

## 6. CAPEX 資金調達恒等式

### 6.1 計画・実行・キャンセル・延期の関係

```
capex_plan_eff_s1 = capex_plan_s1 + plan_carry_s1[t−1]                    … 有効計画（当期に実行しうる計画）
capex_plan_eff_s1 = capex_exec_s1 + capex_cancel_s1 + capex_defer_s1      … 計画の処分（恒等式 1）
capex_cancel_s1   = cancel_s1 · capex_plan_eff_s1                          … 因果グラフ L06・L07
plan_carry_s1     = plan_carry_s1[t−1] + capex_defer_s1 − （当期に復活した繰越分）
```

- **キャンセル**（`capex_cancel_s1`†）は計画から**永久に消える**。将来期に復活しない。
- **延期**（`capex_defer_s1`†）は `plan_carry_s1`† へ繰り越され、将来期の `capex_plan_eff_s1` を増やす。
- どちらも**着工前**の処分であるため、貸借対照表に一切現れない。着工後の取消は `pipe_cancel_s1`（§5.2、MVP `≡ 0`）である。
- この区別が契約 §5.3 の `SH-CAPEX`（8 四半期の一時的な計画削減）と `SH-EXP`（減衰する恒久的な期待下方修正）の帰結を分ける。一時的削減が延期であれば繰越として戻り、キャンセルであれば戻らない。**どちらに配分するかは #169 の行動方程式が決める**が、本書は「両方が同一の恒等式に入り、合計が有効計画に一致すること」を要求する。

### 6.2 資金調達恒等式

```
capex_exec_s1 + div_s1 + tax_s1 + int_burden_s1 + repay_s1 + Δcash_s1
  = ocf_s1 + newdebt_s1 + equity_issue_s1                                  （恒等式 2、s = S1）

invest_s + div_s + tax_s + int_burden_s + repay_s + Δcash_s
  = ocf_s + newdebt_s + equity_issue_s                                     （恒等式 2'、s ∈ SP）
```

これは §5.4 の `cash_s` 更新式の移項であり、**独立の制約ではなく同一の恒等式の別表現**である。Issue #166 §4 が要求する資金源の分解に対応させると次になる。

| Issue #166 §4 の資金源 | 本書の変数 | 符号 |
|---|---|---|
| 営業CF・内部資金 | `ocf_s − int_burden_s − tax_s − div_s` | `+` |
| 現金取り崩し | `−Δcash_s`（`Δcash_s < 0` のとき取崩） | `+` |
| 新規借入・社債発行 | `newdebt_s` | `+` |
| 株式発行または外部資本 | `equity_issue_s`（MVP `≡ 0`） | `+` |
| 借換できなかった元本返済 | `−repay_s` | `−`（資金需要） |
| 投資計画の延期・キャンセル | `capex_cancel_s1 + capex_defer_s1` | 恒等式 1 側で資金需要を減らす |

**閉じ変数の指定（本書の中心的な決定）**

恒等式 1 と恒等式 2 を連立すると、次の形になる。

```
capex_plan_eff_s1 − capex_cancel_s1 − capex_defer_s1
  = ocf_s1 − int_burden_s1 − tax_s1 − div_s1 − repay_s1 + newdebt_s1 + equity_issue_s1 − Δcash_s1
```

**決定**: 左辺と右辺が一致しない場合、**`capex_cancel_s1` と `capex_defer_s1` が閉じ変数**である。すなわち、

- 資金源が不足したとき、差額は**キャンセル・延期という実物側の変数**で埋める。
- **説明のつかない残差項・暗黙の外部資金で埋めない**（§1.2-3）。
- 資金源が余剰のとき、差額は `Δcash_s1`（現金の積み増し）へ回る。

**根拠**: 「CAPEX 削減で消えた支出の行き先」を追跡することが本モデルの目的（Issue #166 の背景）であり、資金不足が残差で埋められると、削減が起きなかったことになってしまう。閉じ変数を実物側に置くことで、**資金制約が必ず実物の投資削減として現れる**。

**#169 への引き渡し**: 資金調達の**順序**（内部資金 → 現金取崩 → 借入 → 増資 → キャンセル・延期）と各段階の上限（`cash_s ≥ st_cash_min_s · sales_s`†、`newdebt_s ≤` 担保・貸出態度による上限）は行動方程式であり #169 が定める。本書が固定するのは「閉じ変数がキャンセル・延期であること」と「上限に達した資金源が次の段階へ送られること」のみである。

### 6.3 増資を初期MVPで恒等的ゼロとする決定

| 検討 | 内容 |
|---|---|
| **決定** | `equity_issue_s ≡ 0`（初期MVP）。独立項として恒等式に保持する |
| **根拠 1** | 増資額を生成するには株式時価総額と発行可能量の関係が必要だが、§3.4 の決定により株式を貸借対照表に持たないため、発行額の上限を会計的に定義できない |
| **根拠 2** | 因果グラフに `EQUITY_VAL → 増資額` のエッジが無い。`L38`（`EQUITY_VAL → COST_CAPITAL_s`）は**株式調達コスト**として資本コストに合成される経路であり、数量としての増資ではない（因果グラフ §6.2 の経路 (a)） |
| **根拠 3** | hyperscaler（`S1`）は内部資金と社債が中心で、増資による CAPEX 調達は稀である。初期MVPの基準ユースケースで支配的な経路ではない |
| **帰結** | 株価下落の資金調達への作用は、**資本コスト経路**（`L38` → `L39` → 計画）と**担保・借換経路**（`L31` → `L32` → `L40`）の 2 つに限定される |
| **将来拡張** | 株式を instrument として導入した時点で `equity_issue_s` に値を入れる。恒等式の形は変えない |

### 6.4 株価下落から実体支出への作用経路

Issue #166 §4 は「株価下落がどの資金調達フローまたは制約へ作用するかを明示し、単なる評価損を実体支出減少と同一視しない」ことを要求する。本書の会計構造における作用点を列挙する。

| # | 経路 | 会計上の作用点 | 作用の性質 |
|---|---|---|---|
| (a) | `equity_val → cost_capital_s`（`L38`）→ `capex_plan_s1`（`L39`） | **恒等式 1 の左辺**（`capex_plan_eff_s1` が小さくなる） | 計画段階。資金制約ではなく意思決定 |
| (b) | `equity_val → collateral`（`L31`）→ `rollover`（`L32`）→ `repay_s = (1 − rollover) · matur_s` | **恒等式 2 の左辺**（`repay_s` が増える＝資金需要が増える） | 現金制約。借換不能分が現金流出になる |
| (c) | `equity_val → collateral → rollover → capex_exec_s1`（`L40`） | **恒等式 1 の閉じ変数**（`capex_defer_s1` が増える） | (b) の帰結として投資が延期される |
| (d) | `equity_val → equity_issue_s` | **作用しない**（`equity_issue_s ≡ 0`、§6.3） | 初期MVPでは経路を持たない |
| (e) | `equity_val → nw_s`（評価損） | **作用しない**（§3.4・§5.6） | 株式を貸借対照表に持たないため、評価損は純資産に現れない |

**契約**:

- **(e) が存在しないことが本書の設計判断の核心である**。株価下落は借り手の純資産・現金・債務のいずれの残高更新式にも現れない。実体支出の減少は、(a) の計画変更または (b)(c) の借換制約を**経由したときのみ**発生する。
- 因果グラフ §6.1 の禁止（`EQUITY_VAL` から `Y_TOT`・`Y_s`・`CONS`・`EMP` への直接エッジ）を、会計側でも構造的に保証する。
- (b) は #164 の因果グラフに**明示的なエッジが無い**作用である（`ROLLOVER` は `CAPEX_EXEC` へのみ接続されている）。借換不能分が現金を消費することは会計上必然であるため、本書は会計制約として記述する。因果グラフへの `ROLLOVER → CASH_s`（会計・`+`・遅れ 0）の追加を差し戻し `B5` として提案する（§10.2）。

## 7. 信用損失・デフォルトの初期扱い

### 7.1 決定

**初期MVPでデフォルトを内生化しない。信用条件の悪化のみを扱う。**

| 扱う | 扱わない |
|---|---|
| スプレッド拡大（`spread`）・貸出態度引き締め（`lend_stance`）・借換条件悪化（`rollover`）・資本コスト上昇（`cost_capital_s`） | デフォルト確率・デフォルト発生・倒産・連鎖倒産 |
| 借換不能に伴う現金流出（`repay_s`、§6.4 (b)） | 貸倒の発生（`writeoff_s ≡ 0`） |
| 返済能力・借換制約の**診断**（§7.3） | 信用損失の `S4` バランスシートへの反映 |

### 7.2 内生化しない根拠

1. **貸倒の吸収先が定義できない**。`nw_s4 ≡ 0`（§3.3）としたため、`S4` に損失を吸収する自己資本が無い。デフォルトを内生化すると `writeoff_s > 0` の相手方が `SX` になり、「モデル外の誰かが損失を負担する」という無内容な処理になる。内生化には (i) `nw_s4` の導入、(ii) `S4` の資金調達コスト、(iii) 自己資本比率制約と貸出数量制約の導入が前提であり、いずれも因果グラフ `1.0.0` に存在しない。
2. **集約部門モデルはデフォルトを表現する粒度を持たない**。倒産は部門内の個別主体の現象であり、契約 §6 が「数千社規模の ABM」「個別企業・銀行のバランスシート」を対象外としている。集約債務比率からデフォルト率を関数として与えることは可能だが、それは較正できない自由度を増やすだけである（#165 §2.3-1 と同じ論法）。
3. **判定問題がデフォルト率を必要としない**。契約 §3 の Q1–Q5 の判定量は産出・投資・雇用・消費・スプレッド・カバレッジ・在庫・稼働率であり、デフォルト率を含まない。§4.2 の `broad_downturn` の 4 指標群にも含まれない。

### 7.3 デフォルトを実装しない場合の診断可能性

デフォルトを持たなくても、**返済能力と借換制約は診断可能でなければならない**（Issue #166 §5）。次の診断量を必須とする。

| 診断量 | 定義 | 意味 | 出所 |
|---|---|---|---|
| `coverage_s` | `ocf_s / int_burden_s` | 営業CFが利払いを賄えるか | #165（Q5 走査変数 ii） |
| `debt_service_s` | `int_burden_s + repay_s` | 利払い＋現金による純元本返済 | #165・本書 §5.4 |
| `dsc_s`† | `ocf_s / debt_service_s` | 返済負担全体のカバレッジ | 本書 |
| `leverage_s` | `debt_s / sales_s` | 債務比率 | #165（Q5 走査変数 i） |
| `rollover_gap_s`† | `(1 − rollover) · matur_s` | 借換できず現金で返済すべき額 | 本書 §5.4 |
| `liquidity_gap_s`† | `debt_service_s + I_s − ocf_s − newdebt_s − (cash_s[t−1] − st_cash_min_s · sales_s)` | 資金調達ギャップ（正なら計画の縮小が必要） | 本書 §6.2 |
| `funding_pressure_s`† | §7.4 の 5 値ラベル | 資金繰り圧力の質的区分 | 本書 |

**契約**: `writeoff_s ≡ 0` であっても `liquidity_gap_s > 0` は発生しうる。その場合に何が起きるかは §6.2 の閉じ変数（キャンセル・延期）で定義済みであり、**デフォルトを持たないことが「資金繰りが常に成立する」ことを意味しない**。この区別を LLM 説明層へ引き渡す（§11）。

### 7.4 Keen の Hedge / Speculative / Ponzi との概念的対応と非同一性

`funding_pressure_s`† の区分を定義する。**Keen 側のラベル名（`hedge` / `speculative` / `ponzi`）を流用しない**。

| ラベル | 条件 | 意味 |
|---|---|---|
| `fp_unlevered` | `debt_s[t−1] ≤ st_debt_tol`† | 実質無借金。区分が無意味な領域を明示的に切り出す |
| `fp_covered` | `ocf_s ≥ debt_service_s − τ` | 営業CFが利払いと純元本返済の双方を賄う |
| `fp_rollover_dependent` | `int_burden_s ≤ ocf_s < debt_service_s − τ` | 利払いは賄うが元本返済は借換に依存する |
| `fp_interest_uncovered` | `ocf_s < int_burden_s − τ` | 利払いすら営業CFで賄えない |
| `fp_invalid` | `NaN` / `Inf` / 発散後 | 誤分類しない（precedence 最上位） |

**Keen の資金調達区分との対応表**

| 観点 | Keen（[Minsky 資金調達区分診断](minsky_regime_diagnostics.md)） | 本モデル | 同一か |
|---|---|---|---|
| 集計単位 | 経済全体の集計（単一の民間債務比率 `d`） | 部門別（`s ∈ SF`） | **異なる** |
| 時間単位 | 連続時間 ODE・年率・産出比 | 離散四半期・水準（10億ドル） | **異なる** |
| 元本返済 | `amortization_rate` という**診断層だけの仮定**（`principal_commitment = amortization_rate · max(d, 0)`） | 満期構成 `st_maturity_s` から生成される**モデル内フロー** `repay_s = (1 − rollover) · φ_s · debt_s[t−1]` | **異なる**（本モデルは診断仮定を持たない） |
| 借換の扱い | 表現しない（元本返済は常に発生する仮定） | `rollover` により借換可能額が変動する | **異なる** |
| 分母 | 営業余剰（産出比） | 営業CF `ocf_s`（利払い前・税引前、水準） | 概念的に対応 |
| ラベルの性質 | 集計モデル上の代理指標。倒産予測ではない | 部門集約の資金繰り圧力区分。倒産予測ではない | **性質は同じ** |

**契約**（[ADR 0006](../adr/0006-cross-model-reasoning-contract.md) の同名変数の非同一視を継承）:

- `fp_rollover_dependent` を Keen の `speculative` と**同一視しない**。両者は元本返済の生成方法が根本的に異なる（診断仮定 vs モデル内フロー）。
- 両モデルの区分系列を**同一の図に重ねて表示しない**。比較する場合は概念対応表（上表）を併記し、比較不能な項目を `insufficient_comparability` として明示する。
- 本モデルの区分は**倒産予測・危機予測ではない**。デフォルトを内生化していない（§7.1）ため、`fp_interest_uncovered` が続いても本モデル内で倒産は発生しない。この限界を LLM 説明層の必須記載事項とする（§11）。

### 7.5 内生化する場合に必要な会計処理（将来拡張）

将来 `writeoff_s > 0` を導入する場合の処理を、恒等式の形を変えずに実現できるよう先に定義する。

| 対象 | 処理 |
|---|---|
| 借り手の債務 | `debt_s = debt_s[t−1] + newdebt_s − repay_s − writeoff_s`（§5.4、既に項として存在） |
| 借り手の純資産 | `Δnw_s` に `+ writeoff_s`（債務免除益、§5.6、既に項として存在） |
| 貸し手の資産 | `loans_s4 = loans_s4[t−1] + Σ(newdebt_s − repay_s − writeoff_s)`（§5.5、既に項として存在） |
| 貸し手の純資産 | **`nw_s4 ≡ 0` を解除する必要がある**（§3.3）。`nw_s4 = nw_s4[t−1] + Σ int_burden_s − 資金調達費用 − Σ writeoff_s` へ変更し、`C-10` の全額移転を廃止する |
| 前提となる追加 | `S4` の資金調達コスト・自己資本比率制約・デフォルト発生関数。いずれも因果グラフの改訂が必要 |

**契約**: 上表の最初の 3 行は本書の恒等式に**既に独立項として含まれている**。内生化に必要な変更は 4 行目（`nw_s4`）と因果グラフの改訂に限られる。この設計により、拡張時に §5・§8 の恒等式を書き換えずに済む。

### 8.2 許容誤差

[SFC 統合設計](sfc_integration_design.md) §4.2 と同一の判定を用いる。**本モデル専用の許容誤差規約を作らない**。

| 項目 | 規約 |
|---|---|
| 判定式 | `abs(residual) ≤ atol + rtol · scale` |
| `scale` | 当該検証に関与する項の**有限な絶対値の最大**（合計ではない） |
| 既定値 | `atol = 1e-8`、`rtol = 1e-6` |
| 上書き | methodology metadata（`SFCMethodologyMetadata.tolerance_abs` / `tolerance_rel`）から上書き可能 |
| 自動補正 | **行わない**。丸め・クリップ・辻褄合わせを禁止する（§1.2-1） |

**注意**: 本モデルは水準（10億ドル）で計算するため `scale` が `10^3` 程度になる。`rtol = 1e-6` は絶対誤差で `10^{-3}`（100万ドル）程度に相当する。20 四半期の累積で系統的な誤差が生じないことは、`:stock_flow` を毎期検証することで担保する。閾値の妥当性は #170 の数値解法頑健性確認で再評価する。

### 8.3 `NaN` / 発散・残差の扱い

| 状況 | 扱い |
|---|---|
| `NaN` / `Inf` | 当該期の該当検証を `acc_invalid` として構造化記録する。**会計違反（`acc_fail`）へ読み替えない**。例外を投げない |
| 欠損 | 検証不能として `acc_warning`・理由を記録 |
| 発散 | ストックが `Inf` または閾値超過となった最初の期を `divergence_time` に記録し、以降を invalid 期に分類する |
| 符号制約違反（`cash_s < 0`・`inv_s < 0`・`backlog_s < 0` 等） | **会計違反ではなくモデルの誤り**として別種の検証（`:sign_constraint`）で検出する。自動クリップしない（#165 §5.1 の方針を継承） |
| `S5` 残差 | `abs(s5_net_sx) / y_tot > 0.05`（既定）の期を `acc_warning` として報告する（§4.5）。閾値は診断層の設定値として外部化する |
| 診断ラベルとの関係 | 会計違反がある期を含むシミュレーションについて、契約 §4.3 の診断ラベルを出力する場合は**会計違反の存在を必ず併記する**。違反を理由にラベルを `indeterminate` へ自動変更はしない（判定は契約 §4.2 の指標で行う） |

**状態型**: `acc_pass` / `acc_warning` / `acc_fail` / `acc_invalid`（既存 `AccountingCheckStatus` を再利用）。

### 8.4 Phase 1 のテスト設計方針

| レイヤー | 内容 |
|---|---|

### 9.2 SIM 型 SFC モデルとの非同一性

既存の [最小 SIM 型 SFC モデル](sim_sfc.md) と本モデルは、いずれも貸借対照表行列・取引フロー行列を持つが、**同一視しない**。

| 観点 | SIM 型 | 本モデル |
|---|---|---|
| 部門 | 家計・政府・生産（3） | `S1`–`S5` + `SX`（6） |
| 金融商品 | 政府貨幣 `H` のみ | 預金・貸出・前受金・モデル外調達（4） |
| 実物資産 | 持たない（在庫・資本なし） | 稼働資本・建設中資本・在庫（3） |
| 企業利潤 | ゼロ（純導管） | 内生（`profit_s`、固定費レバレッジあり） |
| 会計の閉じ方 | 完全に閉じる（残差部門なし） | `SX` を置いて閉じる（`S5` の貯蓄・中間投入・税をモデル外へ帰属） |
| 目的 | 会計が閉じた需要決定の最小骨格 | 部門別 CAPEX・信用循環の判定問題（契約 §3） |

**契約**（[ADR 0006](../adr/0006-cross-model-reasoning-contract.md) の非同一視を継承）:

- 両モデルの部門（`:households` と `S5`、`:production` と `S2`/`S3`）を**同一概念として対応づけない**。
- 両モデルの会計残差・純資産を**同一の比較表に並べない**。比較する場合は `insufficient_comparability` を明示する。
- cross-model 概念 registry へ本モデルを登録する際、`caveats` に「残差部門 `SX` を持つため会計は経済全体で閉じていない」ことを必ず記載する（#167・#171）。

3. 会計は `SX`（モデル外・残差部門）を置いて閉じており、**経済全体で閉じた SFC ではない**。`S5` の貯蓄・純資産は追跡していない。
4. 株価下落の影響を説明する際は、**媒介経路**（資本コスト・借換制約）を必ず明示する。「株価下落が支出を減らす」という直接的な表現を用いない（因果グラフ §6.4）。

## 12. 限界

1. **`S4` の資金制約を表現しない**。`nw_s4 ≡ 0`・`fund_s4` を残差とする設計（§3.3）により、銀行の自己資本・調達コスト・貸出数量制約が信用収縮の要因にならない。初期MVPの信用収縮は価格・条件（スプレッド・貸出態度・借換条件）のみで生じる。銀行側の要因による信用収縮（自己資本毀損による貸し渋り）は表現できない。
2. **`S5` の純資産を追跡しない**。家計貯蓄・非 AI 企業の留保は `s5_net_sx` として `SX` へ流出し、蓄積されない。したがって資産効果（`X01`）・家計信用（`X02`）の将来導入には、家計の金融資産を instrument として追加する会計改訂が必要である。`s5_net_sx` は真の残差であり、その大きさは `S5` 集約の妥当性の指標になる（§8.3 で監視する）。
3. **会計は経済全体で閉じていない**。`SX` を置いて閉じているため、SFC の中心的な検証力（「すべての支出は誰かの所得」が経済全体で成立する）は部分的にしか働かない。`SX` へ流れる項目の規模が大きいほど、会計検証の検出力は下がる。
4. **`S3` の自部門投資に相手方が無い**。`invest_s3` は #164 の `X06`（`S3 → S2` 逆連関）が `EXT` であるため全額 `SX` から調達される。`S3` の投資が国内の受注を生まない非対称な構造になっている。
5. **仮定 A-2 により資本財の納期遅延を表現しない**（§3.5）。`S1`・`S2` の資本財需要は当期に全額引き渡されるものとし、受注残 `backlog_s` に滞留するのは一般需要・モデル外需要のみである。半導体・製造装置の供給制約による CAPEX 実行の遅延は、`capex_pipe_s` の稼働開始ラグとして一括表現され、需給逼迫による納期変動として内生化されない。
6. **前受金・売掛買掛を持たない**（`advance_s ≡ 0`、§4.4）。分割払い・支払サイトを表現しないため、資金繰りのタイミングは実際より単純化される。
7. **評価損益を持たない**（`valchg_s ≡ 0`）。在庫・資本の価格変動、金融商品の時価変動を表現しない。`price_s` が大きく動くシナリオでは、在庫の実質価値と会計上の価値が乖離する。
8. **法人税・政府部門を持たない**（`tax_s ≡ 0`）。財政政策・法人税率変更のシナリオを表現できない。家計税・移転は `pl_tau` による比例控除としてのみ存在する。
9. **会計恒等式の成立はモデルの妥当性を意味しない**。§8 の検証がすべて `acc_pass` でも、行動方程式・パラメータが現実と整合することは保証されない。会計整合性は必要条件であって十分条件ではない。
10. **本書は実データによる検証を経ていない**。部門間配分比・満期構成・賃金換算係数の妥当性は #170 の履歴再生で初めて評価される。
