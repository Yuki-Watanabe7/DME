# LLM出力の安全性・免責・禁止表現ルール

> 関連Issue: #76・#171（2.7 節の追加）
> 関連ドキュメント: [LLM接続層の設計](architecture/llm_layer.md)・[ADR 0005: Keen 実証結果の AI 説明契約](adr/0005-keen-ai-explanation-contract.md)・[ADR 0014: Digital Twin / Digital Shadow の名称使用条件](adr/0014-digital-twin-naming-conditions.md)

---

## 1. 目的と適用範囲

本ドキュメントは、DME が提供する AIエコノミスト機能における LLM 出力の安全性ルールを定める。

DME のマクロ経済モデルは「特定の仮定下での条件付きシミュレーション」であり、実際の経済・市場の動向を予測するツールではない。LLM が生成する自然言語説明についても、この性質を一貫して反映する必要がある。

**適用対象:**
- LLM接続層が生成するすべての自然言語出力（要約・説明・比較・候補提示）
- LLM へ渡すプロンプトのシステム指示部分
- 統合デモ・サンプルスクリプトの出力

---

## 2. 禁止表現

以下の表現・内容は LLM 出力において明示的に禁止する。

### 2.1 断定的な将来予測

**禁止の理由:** DME のモデルはパラメータ仮定のもとでの条件付き反応を計算するものであり、実際の将来経済の予測能力を持たない。

| 禁止表現の例 | 代わりに使うべき表現 |
|---|---|
| 「来年の GDP は〇〇%成長するでしょう」 | 「このモデル設定のもとでは、〇〇ショックに対して Y は T 期以内に定常状態に戻る傾向を示します」 |
| 「インフレ率は今後〇ヶ月で低下します」 | 「金融政策ショックを導入したシナリオでは、このモデル上のインフレ変数は〇期後に収束します（モデル仮定の範囲内）」 |
| 「経済は回復に向かっています」 | 「モデルのシミュレーション上では、ショック後の移行経路は〇期で定常状態に近づきます」 |

**チェック:** 断定的未来時制（「〜するでしょう」「〜になります」「〜が予想されます」）が、モデル設定の文脈から切り離されて単独で現れていないか確認する。

---

### 2.2 投資・売買推奨

**禁止の理由:** DME は学術的なマクロ経済分析ツールであり、個別資産・市場の投資判断ツールではない。

| 禁止表現の例 | 代わりに使うべき表現 |
|---|---|
| 「この結果に基づき、〇〇への投資を推奨します」 | 「本出力は投資判断の根拠として使用することを意図していません」（免責として必ず付記） |
| 「株価は上昇が見込まれます」 | （モデル出力に株価変数が含まれる場合のみ）「モデル上の資産価格変数は〇%の変動を示しますが、これは実際の市場価格を予測するものではありません」 |
| 「今が買い時です」 | 出力禁止。このような表現が生成された場合はシステムレベルで除外すること |

---

### 2.3 政策判断の断定

**禁止の理由:** 政策判断には多くの社会的・政治的・倫理的考慮が必要であり、経済モデル単体から結論を導くことはモデルの分析能力を超えている。

| 禁止表現の例 | 代わりに使うべき表現 |
|---|---|
| 「政府は〇〇政策を採用すべきです」 | 「このシナリオでは、〇〇ショックに対してモデル上の政策変数を変化させると〇〇の効果が観察されます。ただし実際の政策判断には本モデルの仮定外の要因が多数あります」 |
| 「金利を〇%に設定するべきです」 | 「このモデル設定において金利パラメータを〇%に設定したシナリオでは〇〇の結果が得られます」 |
| 「財政拡張は必要です」 | 「財政ショックを導入したシナリオの比較では、モデル上の産出変数に〇%の変動が観察されます」 |

---

### 2.4 根拠不明な因果説明

**禁止の理由:** 因果関係の断言には実証的根拠が必要であり、LLM の確率的出力を因果関係として提示することはユーザーを誤導するリスクがある。

| 禁止表現の例 | 代わりに使うべき表現 |
|---|---|
| 「〇〇が原因でインフレが上昇しました」 | 「このモデルの仮定のもとでは、〇〇ショックを導入するとインフレ変数が上昇するという関係が見られます」 |
| 「技術進歩は必ず雇用を減少させます」 | 「このモデルにおける技術ショックの設定では、特定のパラメータ範囲で雇用変数に〇〇の方向性が観察されます」 |
| 「〇〇政策が景気後退を引き起こした」 | 「〇〇ショックシナリオでは、モデル上の産出変数が〇%低下する経路が観察されます（実際の景気後退の原因分析とは別です）」 |

---

### 2.5 実データとモデル出力の混同

**禁止の理由:** モデル変数（例: モデル上の消費 C）と実データ系列（例: 国民経済計算の家計最終消費支出）はキャリブレーションなしに同一視できない。詳細は [simulation_outputs.md セクション6.2](simulation_outputs.md) を参照。

| 禁止表現の例 | 代わりに使うべき表現 |
|---|---|
| 「日本の GDP は〇〇%成長しています」（モデル出力を指して） | 「Ramsey モデルのシミュレーション上の産出 Y は〇〇の変動を示しています（実際の日本 GDP とは異なります）」 |
| 「実際のデータと一致しているため、予測は信頼できます」 | 「モデル出力を実データと比較した場合、〇〇変数に乖離が観察されます。これはモデルの仮定の限界によるものです」 |
| 「Fed のデータによると〇〇」（FRED データをモデル予測の証拠として） | 「FRED から取得した〇〇系列（実データ）と、このモデルのシミュレーション結果を比較すると、〇期において乖離が大きくなっています」 |

---

### 2.6 Keen 実証分析固有の禁止解釈

Keen の実証分析では、観測データ、測定変換、推定値、モデル出力、diagnostic proxy、感応度を
異なる根拠として扱う。詳細な category、source reference、warning severity、fallback は
[ADR 0005](adr/0005-keen-ai-explanation-contract.md) を正本とする。

| 禁止する解釈 | 必要な限定 |
|---|---|
| calibrated parameter を経済構造の真値、因果 parameter、普遍定数と断定する | 標本、proxy、bounds、initial guess、objective、収束・識別 warning に依存する限定推定値とする |
| in-sample fit をモデル妥当性の十分条件とする | 標本内 metric として、対象期間・変数・初期値方式を併記する |
| out-of-sample fit を因果的妥当性、将来予測保証、政策効果の証明とする | holdout 区間に対する条件付き model trajectory の fit とする |
| observed proxy regime を Keen モデル内部の endogenous regime または企業別実測分類と同一視する | 集計 proxy に操作的診断を適用した結果と明示する |
| 相関、方向一致、転換点・timing 一致だけから危機の因果経路を確定する | 一致した metric と、因果証拠が不足していることを分けて記載する |
| 感応度分析で未検証の parameter・proxy・期間まで頑健性を外挿する | 実際に変更した仮定と範囲内だけで安定性を述べる |
| 欠損、頻度変換、単位差、data vintage / 系列改定を無視して値を直接比較する | measurement metadata と quality flag を併記する |
| 発散後の `NaN` / JSON `null` を 0、Ponzi、または観測値へ読み替える | 欠損または model divergence として扱う |
| context に存在しないデータ、文献、モデル特性を一般知識から補完する | `not_available` または `insufficient_evidence` とする |

推定未収束、弱識別、複数局所解、OOS 悪化、regime 不一致、感応度不安定は、不利な結果であっても
省略してはならない。warning と矛盾する肯定的な結論を本文で生成することも禁止する。

---

### 2.7 モデルの位置づけを誇張する名称

DME または個別モデルの位置づけを、実装が持たない能力を含意する名称で述べることを禁止する。
名称の使用条件は [ADR 0014](adr/0014-digital-twin-naming-conditions.md) を正本とする。

| 禁止する表現 | 理由・代わりに述べてよいこと |
|---|---|
| `Digital Twin` / `デジタルツイン` / `Digital Shadow`（DME 全体または個別モデルを指して） | 継続同期・状態推定・予測誤差更新を含意する。[ADR 0014](adr/0014-digital-twin-naming-conditions.md) の 8 条件（`DS-1`–`DS-4`・`DT-1`–`DT-4`）は現段階でいずれも未充足。代わりに「動学的マクロ経済モデルの計算・比較・説明を行うパッケージ」と述べる |
| 「部分的な Digital Twin」「Digital Twin 的」「Digital Twin を志向した」等の緩和表現 | 名称の含意だけを実装の裏付けなしに借りる。充足した条件を個別の事実として述べる（例:「実データを取得・変換して較正・検証できる」「fixture により再現可能である」） |
| 「経済をリアルタイムで再現する」「実体経済と同期している」 | 自動更新も乖離の継続記録も持たない。「分析者が実行したときに取得・変換・較正が走る単発のパイプラインである」と述べる |
| モデルを「経済のシミュレーター」として無限定に述べる | 「特定の仮定下での条件付きシミュレーション」という 1 節の位置づけを維持する |

## 3. 必須表現・必須記載事項

LLM 出力には以下の情報を必ず含める。プロンプトテンプレートに組み込むことで確実に反映する。

### 3.1 モデルの限界の明示

すべての説明・要約において、使用したモデルの主要な仮定と限界を明示する。

**記載すべき内容:**
- モデルの種類（例: 「これは閉鎖経済・代表的家計を仮定した Ramsey モデルです」）
- 分析が成立する前提条件（例: 「パラメータは長期平均に基づくキャリブレーション値です」）
- モデルが捨象している重要な要因（例: 「このモデルは名目硬直性・摩擦・不確実性を含みません」）

**最低限の記載例:**
> このシミュレーションは [モデル名] に基づいています。仮定: [主要仮定リスト]。これらの仮定が成立しない状況への適用には注意が必要です。

---

### 3.2 データの出所の明示

実データを参照または比較に使用する場合、出典を必ず明示する。

**記載すべき内容:**
- データソース（例: FRED、e-Stat、日本銀行統計、内閣府）
- 系列識別子（例: `FRED/GDPC1`）
- 参照期間（例: 2000Q1–2023Q4）
- 実データとモデル変数の対応関係（[variable_mapping.md](data/variable_mapping.md) 参照）

**記載例:**
> 実データ: FRED GDPC1（実質 GDP、季節調整済、年率換算）2000Q1–2023Q4。モデル上の産出変数 Y との比較はキャリブレーションなしの参考比較です。

---

### 3.3 前提条件の明示

使用したパラメータ値・初期条件・ショック設定を明示する。

**記載すべき内容:**
- 主要パラメータ値（α, β, δ 等）
- 初期状態（定常状態からの乖離等）
- ショックの種類・大きさ（IRF の場合）

**記載例:**
> パラメータ設定: α=0.33（資本分配率）, β=0.99（割引因子）, δ=0.025（資本減耗率）。技術ショック ε₀=0.01（1%の正の技術ショック）を導入した場合の IRF です。

---

### 3.4 不確実性の明示

モデル出力の数値は確定的な計算結果であるが、その解釈には不確実性が伴う。

**記載すべき内容:**
- パラメータの不確実性（例: 「パラメータ値の変化に対する感度は示されていません」）
- モデル仮定の不確実性（例: 「代表的家計仮定が現実から外れる場合、結果は異なる可能性があります」）
- 実データ比較における測定誤差（該当する場合）

**記載例:**
> この結果はパラメータを固定した条件付き計算です。パラメータ感度を確認するには感度分析（複数パラメータでの比較シナリオ）を推奨します。

---

### 3.5 追加検証の必要性の明示

LLM 出力が分析補助であることを示し、ユーザーが独立して検証できるよう誘導する。

**記載すべき内容（状況に応じて選択）:**
- 推奨する追加分析（感度分析・別モデルでの確認等）
- 参照すべきドキュメント
- 専門家への相談が必要な局面の示唆

**記載例:**
> 本出力はモデルシミュレーションの補助説明です。政策判断・投資判断への適用には、より詳細な実証分析や専門家の判断が必要です。

---

### 3.6 Keen 実証説明の必須構造と根拠参照

Keen 実証説明では、通常の免責に加えて次を必須とする。

1. 分析対象と期間
2. 観測された事実
3. 測定・データ変換
4. キャリブレーション結果
5. in-sample / out-of-sample 検証
6. regime 診断
7. 感応度・頑健性
8. 解釈可能な範囲
9. 限界・代替説明
10. 根拠参照と再現情報

各主要主張は context の source ID を 1 件以上参照し、`[観測]`、`[測定・変換]`、`[推定]`、
`[モデル出力]`、`[診断proxy]`、`[感応度]`、`[限界]` のいずれかを表示する。情報がない section を
省略せず、未実施なら `not_available`、入力はあるが根拠不十分なら `insufficient_evidence` とする。

出力 JSON が parse 不能、必須 section が欠落、source ID が未登録、または warning severity と結論が
矛盾する場合は、provider の自由文を表示せず [ADR 0005 §7](adr/0005-keen-ai-explanation-contract.md#7-schema-validation-と-fallback)
の決定的 fallback を返す。

## 4. プロンプト安全指示テンプレート

LLM へのプロンプトには、以下のシステム指示テンプレートを組み込む。

### 4.1 基本システム指示テンプレート

```
あなたは動学的マクロ経済モデル（DME）の分析補助AIです。

【役割】
- モデルのシミュレーション結果を経済学的観点から説明・要約する
- モデルの仮定・限界・解釈上の注意点をユーザーに伝える
- 次に検討すべき分析の候補を提示する

【必ず守るルール】
1. すべての説明は「このモデルの仮定のもとでは」という文脈で行う
2. 断定的な将来予測を行わない（「〜するでしょう」「〜が予測されます」単独使用禁止）
3. 投資判断・売買推奨を行わない
4. 政策判断を断定しない（「〜すべき」はモデルシナリオの文脈でのみ使用可）
5. 根拠のない因果説明を行わない
6. 実データとモデル出力を区別して扱い、混同しない

【必ず含める情報】
- 使用モデルの種類と主要仮定
- パラメータ設定・ショック設定（該当する場合）
- データ出典（実データを参照する場合）
- モデルの限界・解釈上の注意点
- 免責文言（「本出力は投資判断・政策立案の根拠として使用することを意図していません」）
```

---

### 4.2 シミュレーション結果要約テンプレート

```
以下のシミュレーション結果を経済学的に要約してください。

モデル: {model_name}
主要仮定: {model_assumptions}
パラメータ: {parameters}
ショック設定（IRFの場合）: {shock_description}

シミュレーション結果サマリー:
{simulation_summary}

要約の要件:
- 定常状態・移行経路・収束速度を経済学的メカニズムと結びつけて説明する
- 数値の単純な読み上げにとどまらず、なぜそのような動態になるかを説明する
- 説明の根拠となったモデル仮定を明示する
- 以下の免責を必ず含める:
  「このシミュレーションは特定の仮定に基づく条件付き計算です。実際の経済動向の予測ではありません。」
- 感度確認など、次に検討すべき分析候補を1〜3点提示する
```

---

### 4.3 実データ比較説明テンプレート

```
以下のモデル出力と実データの比較結果を説明してください。

モデル: {model_name}
実データ出典: {data_source}（系列: {series_id}、期間: {period}）
モデル変数との対応: {variable_mapping}

比較結果サマリー:
{comparison_summary}

説明の要件:
- モデル出力と実データを明確に区別して扱う
- 乖離が観察される場合、考えられるモデル仮定の限界を説明する
- キャリブレーションなしの比較であることを明示する
- 「実データと一致するからモデルが正しい」という結論を避ける
- 以下を必ず含める:
  「実データとモデル出力の比較はキャリブレーションなしの参考比較です。
   モデル変数と実データ系列の対応については variable_mapping.md を参照してください。」
```

---

### 4.4 シナリオ比較説明テンプレート

```
以下の複数シナリオの比較結果を説明してください。

比較シナリオ:
{scenarios_summary}

説明の要件:
- 各シナリオの違い（パラメータ・ショック・モデル）を明確に示す
- 差異の背後にある経済学的メカニズムを説明する
- 「パラメータAを増やすと〜になる」という条件付きの表現を使う
- 「〜のほうが良い」「〜を選ぶべき」といった推奨・判断は行わない
- モデルが捨象している要因を注記する
```

## 5. LLM出力チェックリスト

LLM が生成した出力を評価・レビューする際の確認項目。

### 5.1 禁止表現チェック

- [ ] 断定的な将来予測がモデル文脈から切り離されて使われていないか
- [ ] 「〜に投資すべき」「〜を買うべき」等の投資推奨がないか
- [ ] 「政府は〜すべき」「中央銀行は〜べき」等の政策断定がないか
- [ ] モデルの仮定なしに「〜が原因で〜が起きた」という因果断言がないか
- [ ] 実データとモデル出力が同一視されていないか（「日本の GDP が〜」をモデル出力に使うなど）
- [ ] `Digital Twin` / `デジタルツイン` / `Digital Shadow`、およびその緩和表現（「部分的な〜」「〜的」「〜を志向した」）が使われていないか（2.7 節・[ADR 0014](adr/0014-digital-twin-naming-conditions.md)）
- [ ] 「リアルタイム」「実体経済と同期」等、自動同期を含意する表現が使われていないか

### 5.2 必須記載チェック

- [ ] 使用モデルの種類と主要仮定が明示されているか
- [ ] パラメータ値・ショック設定が記載されているか（シミュレーション出力の場合）
- [ ] 実データの出典・系列・期間が記載されているか（実データ参照の場合）
- [ ] モデルの限界・解釈上の注意点が含まれているか
- [ ] 以下の免責文言（または同等の文言）が含まれているか:
  > 「本出力は投資判断・政策立案の根拠として使用することを意図していません」

### 5.3 表現品質チェック

- [ ] 数値の単純な読み上げにとどまらず、経済的意味が付与されているか
- [ ] 不確実性（パラメータ感度・モデル仮定の限界）が示されているか
- [ ] 次に検討すべき分析の候補が提示されているか（候補の提示であり、断定的指示ではない）
- [ ] モデル変数と実データ変数が明確に区別されているか

### 5.4 Keen 実証説明チェック

- [ ] 観測、測定・変換、推定、モデル出力、diagnostic proxy、感応度が label と型で分離されているか
- [ ] 数値・期間・系列・methodology に関する主要主張が登録済み source ID を参照しているか
- [ ] calibrated parameter を真値・因果 parameter・普遍定数として扱っていないか
- [ ] in-sample / out-of-sample が別々に報告され、fit を因果妥当性や予測保証へ昇格させていないか
- [ ] observed proxy regime と literature / calibrated model diagnosis が別々に表示されているか
- [ ] 感応度の結論が検証済み scenario / 範囲を超えていないか
- [ ] 未収束・弱識別・OOS 悪化・発散・regime 不一致・感応度不安定が本文の結論へ反映されているか
- [ ] 全必須 section があり、情報不足が `not_available` / `insufficient_evidence` で明示されているか
- [ ] context にない知識を補完していないか

## 6. 統合デモへの反映方針

統合デモ（`examples/` 配下のスクリプト）において LLM 出力を含む場合、以下を守る。

### 6.1 デモ出力に含めるべき要素

- シミュレーション結果の数値サマリー
- 使用モデル・パラメータ・仮定の明示
- LLM 生成テキストと計算結果の明確な区別（例: `[モデル計算結果]` vs `[AIによる解説]` のような表示分離）
- 免責文言（デモ末尾または説明ブロックに）

### 6.2 デモ出力の禁止事項

- モデル出力を「経済予測」として提示することを禁止
- 実データとモデル変数を同一スケールで無注釈に重ねることを禁止（比較の場合は注釈必須）
- LLM 生成テキストをモデル計算結果であるかのように提示することを禁止

### 6.3 デモ出力の免責文言例

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【免責事項】
本デモ出力は Ramsey/RBC/Solow 等の学術的マクロ経済モデルの
シミュレーション結果に基づく分析補助です。

- 実際の経済動向・市場動向を予測するものではありません
- 投資判断・政策立案の根拠として使用することを意図していません
- すべての結果は特定の経済学的仮定に基づいており、仮定が異なると結果も異なります
- 実データとの比較はキャリブレーションなしの参考比較です
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
