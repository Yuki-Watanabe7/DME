# LLM接続層の設計ドキュメント

> Phase 6 / P0
> 関連Issue: #69

---

## 1. 背景と目的

Phase 6 では LLM を接続し、モデル結果・実データ比較・ドキュメントをもとに自然言語で説明できる「AIエコノミスト」としての機能を拡張する。

ただし、LLM を早い段階で下位層（モデル層・シミュレーション層・実データ接続層）に混ぜると、次の問題が生じる。

- モデル層・データ層・解釈層の責務が曖昧になる
- LLM 出力に基づく「説明」が検証不能になる
- 根拠不明な予測・断言がシステムに紛れ込む

本ドキュメントは LLM接続層の責務・入出力仕様・禁止事項・安全性方針を明文化し、Phase 6 以降の実装前における設計基準とする。

---

## 2. 全体アーキテクチャにおける位置づけ

[AIエコノミスト化アーキテクチャ](ai_economist.md) に示した層構成において、LLM接続層は最上位の「LLM解釈層」に対応する。

```
┌─────────────────────────────────────────────────────────┐
│  LLM接続層（本ドキュメントの対象）                        │
│  自然言語による説明・要約・分析候補提示                    │
│  inputs: AnalysisContext (後述)                          │
└────────────────────────┬────────────────────────────────┘
                         │ 読み取り専用
┌────────────────────────▼────────────────────────────────┐
│  ドキュメント/RAG層                                      │
│  docs/ の構造化・検索・文脈提供                           │
└──────────────┬─────────────────────┬────────────────────┘
               │                     │
┌──────────────▼──────┐  ┌───────────▼──────────────────┐
│  実データ接続層       │  │  可視化層                     │
└──────────────┬──────┘  └───────────┬──────────────────┘
               │                     │
┌──────────────▼─────────────────────▼──────────────────┐
│  シミュレーション層・モデル層 ← LLM依存なし             │
└────────────────────────────────────────────────────────┘
```

**基本原則**: LLM呼び出しは LLM接続層に閉じる。下位層（モデル層・シミュレーション層・実データ接続層・可視化層）はLLMに依存せず、LLMなしで完全に動作する。

## 3. LLM接続層の責務

LLM接続層が担う責務は以下の5つに限定する。

### 3.1 モデル説明

モデルのメタ情報とドキュメントをもとに、そのモデルの経済学的意味・仮定・適用範囲を自然言語で説明する。

- 対象: モデル名・状態変数・操作変数・パラメータ・モデル解説ドキュメント
- 出力: モデルの前提・仮定・主要メカニズムの説明文
- 注意: 実装の内部詳細（ソルバーの種類・数値手法）は説明の主眼としない

### 3.2 シミュレーション結果要約

`SimulationResult` の数値サマリーをもとに、定常状態・移行経路・IRF の結果を自然言語で要約する。

- 対象: SimulationResult サマリー・変数名・期間・定常状態値
- 出力: 「〇〇ショック後にYは▲%上昇し、T期後に定常状態へ収束した」といった要約文
- 注意: 数値の読み上げに留まらず、経済的意味を付与すること。ただし根拠なき断言は禁止

### 3.3 シナリオ比較説明

複数の `SimulationResult`（異なるパラメータ・ショック・モデル）を受け取り、シナリオ間の差異を言語化する。

- 対象: 複数の SimulationResult サマリーとそれぞれのモデルメタ情報
- 出力: 「パラメータAを増加させると、定常状態での消費はX%増加するが、移行期間が長くなる」といった比較説明
- 注意: 数値の差異の背後にある経済メカニズムを説明するのが役割。予測や推奨ではない

### 3.4 実データとの乖離説明

モデル出力と実データの乖離を受け取り、考えられるモデル仮定の限界や解釈上の注意点を説明する。

- 対象: 乖離のサマリー（乖離幅・方向・期間）・モデルの仮定リスト・データの出典情報
- 出力: 「このモデルはX仮定のため、Yという局面では乖離が大きくなる傾向がある」といった解釈補助文
- 注意: 乖離の存在をもってモデルを否定したり、実データとモデル出力を同一視してはならない

### 3.5 次に見るべき分析候補の提示

ユーザーの現在の分析状況をもとに、次に検討すべき分析の候補を提示する。

- 対象: 現在実行されたシミュレーション情報・実データ比較結果・ユーザーの分析文脈
- 出力: 「次は感度分析として〇〇パラメータを変化させた比較を見ることを推奨します」といった候補リスト
- 注意: あくまで候補の提示であり、特定の行動を断定的に指示しない

## 4. 入力仕様（AnalysisContext）

LLM接続層への入力は `AnalysisContext` 構造体にまとめて渡す。後続の `AnalysisContext` 設計Issueにおいて詳細を定めるが、含むべき要素は以下のとおり。

### 4.1 model_metadata

モデルの識別情報と変数リスト。

| フィールド | 型 | 内容 |
|---|---|---|
| `model_name` | `String` | モデルの識別名（例: `"RamseyModel"`） |
| `state_variables` | `Vector{Symbol}` | 状態変数のリスト（例: `[:K]`） |
| `control_variables` | `Vector{Symbol}` | 操作変数のリスト（例: `[:C]`） |
| `parameters` | `NamedTuple` | パラメータ名と値 |

### 4.2 docs_excerpts

LLM の文脈として提供するドキュメント抜粋。RAG 層が検索・選択して渡す。

| フィールド | 型 | 内容 |
|---|---|---|
| `model_doc` | `String` | `docs/models/` の関連セクション抜粋 |
| `output_guide` | `String` | `docs/simulation_outputs.md` の変数解釈セクション抜粋 |
| `caveats_doc` | `String` | モデルの限界・注意事項の抜粋 |

### 4.3 simulation_result_summary

`SimulationResult` から生成した数値サマリー。元の `SimulationResult` 全体ではなく要約を渡す。

| フィールド | 型 | 内容 |
|---|---|---|
| `steady_state` | `NamedTuple` | 各変数の定常状態値 |
| `key_statistics` | `NamedTuple` | 平均・標準偏差・最大偏差等の統計量 |
| `n_periods` | `Int` | シミュレーション期間数 |
| `shock_description` | `Union{String, Nothing}` | ショックの種類と大きさの説明（IRFの場合） |

### 4.4 data_comparison_summary

実データとの比較結果サマリー（実データ比較を行った場合のみ）。

| フィールド | 型 | 内容 |
|---|---|---|
| `data_source` | `String` | 実データの出典（例: `"FRED/GDPC1"`） |
| `comparison_period` | `Tuple{Int,Int}` | 比較対象期間 |
| `deviation_statistics` | `NamedTuple` | 乖離の平均・最大・方向 |
| `data_caveats` | `Vector{String}` | データ固有の注意事項 |

### 4.5 caveats

LLM の出力に必ず含めるべき免責・注意事項のリスト。呼び出し元が明示的に渡す。

| フィールド | 型 | 内容 |
|---|---|---|
| `model_limitations` | `Vector{String}` | モデル仮定の限界リスト |
| `data_limitations` | `Vector{String}` | データ制約・信頼性の注意事項 |
| `interpretation_warnings` | `Vector{String}` | 解釈上の警告（例: 対数偏差であること） |

## 5. 出力仕様

LLM接続層の出力は構造化された形式で返す。

### 5.1 natural_language_explanation

自然言語による主説明テキスト。

- 経済的意味を含む説明であること
- 数値の単純な読み上げに留まらないこと
- 使用した仮定・前提を明示すること

### 5.2 assumptions

説明の根拠となった仮定・前提のリスト。

- モデル仮定（例: 「このモデルは閉鎖経済を仮定しています」）
- 解釈上の前提（例: 「対数偏差での比較です」）
- 参照したドキュメント（例: `docs/models/ramsey.md` セクション3）

### 5.3 caveats

説明に付随する注意事項・免責事項のリスト。入力の `caveats` をそのまま出力に含める。LLM が独自に追加した注意事項があればそれも含める。

### 5.4 suggested_next_analysis

次に検討すべき分析の候補リスト（3.5 の出力に対応）。

- 候補の種類（感度分析・別モデルでの比較・実データ期間の拡張 等）
- 候補を提示する理由の一言説明
- 断定的な推奨ではなく候補として提示すること

## 6. 禁止事項

LLM接続層において、以下の出力・動作は明示的に禁止する。

### 6.1 投資助言の断定

**禁止**: 「このシミュレーション結果に基づき〇〇に投資すべきです」といった断定的な投資判断の表明。

**理由**: DME のモデルは特定の仮定下での条件付きシミュレーションであり、実際の投資判断に直結させることは設計外（[ai_economist.md セクション7](ai_economist.md) 参照）。

### 6.2 根拠不明な予測

**禁止**: モデルの計算結果や実データに依拠しない将来予測の断言。

**理由**: LLM の確率的な出力を経済予測として提示することは、根拠のない情報をユーザーに信頼させるリスクがある。

### 6.3 実データとモデル出力の混同

**禁止**: モデルのシミュレーション結果を実際の経済指標として扱う表現、またはその逆。

**理由**: モデル変数（例: モデル上の消費 C）と実データ系列（例: 国民経済計算の家計最終消費）は、キャリブレーションなしに同一視できない（[simulation_outputs.md](../simulation_outputs.md) セクション6.2 参照）。

### 6.4 政策判断の断定

**禁止**: 「このモデルの結果から、政府は〇〇政策を採用すべきです」といった政策判断の断定。

**理由**: モデルは特定の仮定に基づく分析ツールであり、政策的含意は多くの考慮事項を要する。モデル単体から政策判断を断定することは分析の限界を超えている。

## 7. 下位層へのLLM依存を持ち込まない方針

**LLM呼び出しは LLM接続層に閉じる。** これは DME のアーキテクチャにおける最重要原則の一つである。

### 7.1 禁止される実装パターン

以下の実装パターンは明示的に禁止する。

| 禁止パターン | 具体例 |
|---|---|
| モデル層でのLLM呼び出し | `simulate()` 内で LLM API を呼んでパラメータを推定する |
| シミュレーション層でのLLM呼び出し | `to_simulation_result()` 内で結果を自動要約する |
| 実データ接続層でのLLM呼び出し | `fetch()` や `preprocess()` 内でデータの意味をLLMに解釈させる |
| 可視化層でのLLM呼び出し | `plot_result()` 内でグラフのキャプションをLLMに生成させる |

### 7.2 理由

- **テスト可能性**: 下位層がLLMに依存すると、単体テストが確率的になり再現性が失われる
- **責務の明確化**: 数値計算の正確性と自然言語生成の品質は、独立した評価軸であるべき
- **モデルの完全性**: モデル層の結果はLLMなしで完全に解釈可能であるべき。LLMは付加的な説明ツールである
- **障害の分離**: LLM API が利用不可・遅延・コスト制限などの状態でも、モデル計算・可視化・実データ比較は動作すること

### 7.3 LLMなしでの完全動作の保証

以下の機能はLLM APIへのアクセスなしに動作することを設計上保証する。

- `steady_state` / `transition_path` / `simulate` / `impulse_response`（モデル層）
- `to_simulation_result`（シミュレーション層）
- `plot_result` / `compare_results`（可視化層）
- `fetch` / `preprocess`（実データ接続層）

## 8. 安全性・免責ルールとの関係

本ドキュメントの禁止事項（セクション6）は、DME の安全性・免責方針に基づく。

### 8.1 関連する設計原則

[ai_economist.md セクション7](ai_economist.md) に記載の「直近では実装しないこと」と本ドキュメントの禁止事項は整合している。

| ai_economist.md セクション7 の項目 | 本ドキュメントでの対応 |
|---|---|
| LLMによる自動予測 | セクション6.2（根拠不明な予測の禁止） |
| 投資判断の自動化 | セクション6.1（投資助言の断定の禁止） |
| 実データとの無検証な同一視 | セクション6.3（混同の禁止） |

### 8.2 免責事項の明示義務

LLM接続層の出力には、必ず以下の免責事項を含めること。

1. **モデルの性質**: このシステムは学術的なマクロ経済モデルのシミュレーションツールであり、実際の経済・市場の動向を予測するものではない
2. **投資・政策への不適用**: 本出力は投資判断・政策立案の根拠として使用することを意図していない
3. **モデル仮定の制約**: すべての結果は特定の経済学的仮定に基づいており、その仮定が成立しない状況には適用できない

### 8.3 安全性・免責ルールの詳細

本ドキュメントのセクション6・8.2 が定める設計原則の詳細（禁止表現の具体例・必須記載事項・プロンプトテンプレート・出力チェックリスト）は、専用の安全性ドキュメントに記載する。

**→ [LLM出力の安全性・免責・禁止表現ルール](../llm_safety.md)**

プロンプト実装時は必ず上記ドキュメントのテンプレート（セクション4）を使用し、出力レビューにはチェックリスト（セクション5）を適用すること。

具体的な安全フィルタ・出力検証・プロンプトインジェクション対策の実装は、Phase 6 の後続Issueにて別途定める。

以下は Phase 6 の後続作業であり、本ドキュメントのスコープ外とする。

| 項目 | 理由 |
|---|---|
| LLM API接続の実装 | 設計基準確立後の実装フェーズで対応 |

| RAG実装 | ドキュメント/RAG層の別Issueで対応 |
| UI/チャット機能 | 上位アプリケーション層の問題 |
